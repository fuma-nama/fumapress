---
title: Views
description: Add pages outside your content, rendered by a Vue component of your theme.
---

A view is a page outside your content. The server gives its props, and a component of your theme renders it. `.views()` of `press.config.ts` adds the views of your site, by name. This one adds a `/releases` page that lists the pages of a `changelog` source:

```ts title="press.config.ts"
export default createPress({ docs: docs.toFumadocsSource(), changelog })
  .plugins(changelogPlugin)
  .views({
    releases: {
      path: "/releases",
      data: { title: "Releases" },
      view({ lang }) {
        const releases = this.getPages(lang).flatMap((page) =>
          page.type === "changelog" ? [{ title: page.data.title, url: page.url }] : [],
        );
        return { releases };
      },
    },
  })
  .config({ site: { name: "Acme" } });
```

`.views()` comes after `.plugins()` and before `.config()`, and each call is optional. `view` receives the `params` of the URL and its `lang`, and returns the props of the page. `this` is the [context](/plugins/context) of the site. The theme renders the page with the component of its [`views`](/theme#page-types) named after the view:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import type app from "../press.config";

export default defineTheme<typeof app>({
  extends: defaultTheme,
  // loaded by the pages of the view
  views: { releases: () => import("./views/Releases.vue") },
});
```

The [view component](/theme#typed-view-components) receives the page as its `page` prop, with the props of the view in `page.props`, and renders the whole page with its own layout. The [home layout](/ui#landing-pages) has the navbar of your site:

```vue title="src/views/Releases.vue"
<script setup lang="ts">
import { Link, type PageOf } from "@fumapress/vue/client";
import HomeLayout from "@fumapress/vue/theme/layouts/home";
import type app from "../../press.config";

defineProps<{ page: PageOf<typeof app, "releases"> }>();
</script>

<template>
  <HomeLayout>
    <div class="mx-auto w-full max-w-(--fd-layout-width) px-4 py-12">
      <h1 class="mb-6 text-2xl font-semibold">{{ page.pageData.title }}</h1>
      <ul class="flex flex-col gap-2">
        <li v-for="release in page.props.releases" :key="release.url">
          <Link :href="release.url" class="block rounded-lg border p-4 hover:bg-fd-accent">
            {{ release.title }}
          </Link>
        </li>
      </ul>
    </div>
  </HomeLayout>
</template>
```

`defineTheme<typeof app>()` requires a component for each view in the theme's own `views`, with a type error that names the view, and checks that it receives the pages of its view. A view without a component also fails to render, with an error that names it.

The props are sent to the browser, so every value must be serializable, like strings, numbers, lists and plain objects. `PageOf<typeof app, "releases">` has the props as JSON: a `Date` is a string there.

A view has its own name: a name of `.views()` that is also the key of a source is a type error and fails when the site starts, and one that is also the name of a view of a plugin fails when that view renders.

A content page wins over a view at its URL. A view without params at the URL of a content page fails when the site starts, since it would never render. A view with params answers the URLs that have no content page: `/guide/[name]` renders `/guide/other`, while `/guide/install` stays the page of `content/guide/install.mdx`.

## Params

A view path takes params like an [API route](/plugins/routes#path-params). `view` receives their values in `params`, and returns nothing for a page that doesn't exist, which is a `404`:

```ts
const posts: Record<string, string> = { hello: "Hello", bye: "Bye" };

createPress(docs.toFumadocsSource()).views({
  post: {
    path: "/blog/[slug]",
    staticPaths: Object.keys(posts),
    view: ({ params: { slug } }) => (slug && posts[slug] ? { title: posts[slug] } : undefined),
  },
});
```

## Render Mode

Views are generated at build time by default, like the pages of a static source, and the sitemap lists them. A view with params generates one page per entry of `staticPaths`, and a `view` that returns nothing for one of them fails the build.

With `render: "dynamic"`, a view renders on demand, and needs a [server deployment](/deploy). The sitemap lists a view without params whatever its render mode. A view that reads your content follows its render mode with `this.getContentRender()`, so it renders on demand when a source is dynamic.

## Page Data

`data` of a view sets the data of its pages, like the `title` and `description` of their `<head>`. The component of the view reads it in `page.pageData`.

For data that differs per page, like the title of a tag page, `data` is a function. It receives the `params` and `lang` of the page, and `this` is the context of the site:

```ts title="press.config.ts"
createPress(docs.toFumadocsSource()).views({
  tag: {
    path: "/tags/[tag]",
    staticPaths: ["news", "release"],
    view: ({ params }) => ({ tag: params.tag }),
    data: ({ params }) => ({ title: `Posts tagged ${params.tag}` }),
  },
});
```

For data from what `view` loaded, like the title of a post from a CMS, write a [view of a plugin](#views-of-plugins), whose `view` returns the data with the props.

## Languages

On a site with [languages](/i18n), a view exists in every language, with the language prefix before its path: `/releases` is also `/cn/releases`. `view` receives the language in `lang`, to list the pages of that language with `this.getPages(lang)`.

## Views of Plugins

A plugin adds views with `createView()` in its `routes` hook. Its `view` returns the `type` of the view with its `props`. A plugin declares the props of its views in its types, so `createView()` takes only those types with their props, and the site has them in its types:

```ts title="releases-plugin.ts"
import type { AppShape, Plugin } from "@fumapress/vue/config";

interface ReleasesProps {
  releases: { title: string; url: string }[];
}

export function releasesPlugin<C extends AppShape>(): Plugin<
  C,
  { views: { releases: ReleasesProps } }
> {
  return {
    name: "acme:releases",
    routes({ createView }) {
      createView({
        path: "/releases",
        data: { title: "Releases" },
        view: ({ lang }) => ({
          type: "releases",
          props: {
            releases: this.getPages(lang).map((page) => ({ title: page.url, url: page.url })),
          },
        }),
      });
    },
  };
}
```

`C` is the site the plugin is added to, so the hooks receive its pages and languages.

The server can't send a component, so the component of a view of a plugin is in the theme. A plugin package can ship a theme with the components of its views, which a site names in `extends`:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import { releasesTheme } from "acme-releases/theme";
import type app from "../press.config";

export default defineTheme<typeof app>({
  extends: [defaultTheme, releasesTheme],
  views: { ...releasesTheme.views },
});
```

`defineTheme<typeof app>()` requires the component of each view in the theme's own `views`, so the theme above spreads the components of the plugin there.

A view of a plugin can return `data` with its `type` and `props`, for data that differs per page, like the title of each post. It wins over the `data` of `createView()`:

```ts
createView({
  path: "/blog/[slug]",
  staticPaths: Object.keys(posts),
  data: { description: "A post of the blog" },
  view: ({ params: { slug } }) => {
    if (!slug || !posts[slug]) return;
    return { type: "post", props: { title: posts[slug] }, data: { title: posts[slug] } };
  },
});
```

To add a view in one language only, pass `lang` to `createView()`:

```ts
createView({
  path: "/newsletter",
  lang: "en",
  view: () => ({ type: "newsletter", props: {} }),
});
```
