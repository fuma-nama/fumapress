A plugin is an object with a `name` and hooks. Add it to your site with `.plugins()`:

```ts title="press.config.ts"
import { createPress } from "@fumapress/vue/config";
import { content } from "@fumapress/vue/content";

export default createPress(content).plugins({
  name: "site:status",
  routes({ createApi }) {
    createApi({
      path: "/api/status",
      GET: () => Response.json({ pages: this.getPages().length }), // [!code highlight]
    });
  },
});
```

`this` in a hook is the [context](/plugins/context) of the site: its config, its pages and helpers for URLs. Hooks run on the server only, so a plugin can read files, call APIs and use secrets.

To share a plugin, export a function that returns it, and type it with `Plugin`:

```ts title="status-plugin.ts"
import type { Plugin } from "@fumapress/vue/config";

export function statusPlugin(options: { path?: string } = {}): Plugin {
  return {
    name: "acme:status",
    routes({ createApi }) {
      createApi({ path: options.path ?? "/api/status", GET: () => Response.json({ ok: true }) });
    },
  };
}
```

Each plugin needs a unique `name`. A site with two plugins of the same name fails to start.

## Hooks

| Hook                    | What it does                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| `routes`                | Adds [API routes](/plugins/routes) and [pages](/plugins/views).                                  |
| `middleware`            | Handles every request before the routes and pages. See [Middleware](/plugins/routes#middleware). |
| `head`                  | Adds tags to the `<head>` of a page.                                                             |
| `layoutProps`           | Adds navbar links and other props of the layouts, per language.                                  |
| `transformPage`         | Adds to the data of a page that the browser receives, like its title.                            |
| `getPageBody`           | Renders the pages of a [content source](/plugins/content).                                       |
| `getPageToc`            | Gives the table of contents of a page.                                                           |
| `getPageText`           | Gives the Markdown of a page, for `llms-full.txt`.                                               |
| `getPageStructuredData` | Gives the headings and text of a page, for search.                                               |
| `getPageLastModified`   | Gives the date a page last changed, for the sitemap and the page.                                |
| `init`                  | Runs when the site starts, before the content loads.                                             |
| `configureLoader`       | Adds options to the Fumadocs content loader.                                                     |
| `configure`             | Runs when the site starts, after the content loads.                                              |
| `build`                 | Runs once when the site is built. See [Build](/plugins/build).                                   |

`head` and `layoutProps` take the same values as the `head` and `ui.layoutProps` options of your [config](/config):

```ts title="press.config.ts"
createPress(content).plugins({
  name: "site:extras",
  head: () => [{ tag: "meta", attrs: { name: "theme-color", content: "#0ea5e9" } }],
  layoutProps({ lang }) {
    return { links: [{ text: "Blog", url: this.localizePath(lang, "/blog") }] };
  },
});
```

## Plugin Order

Plugins run in this order:

1. Your plugins, in the order of `.plugins()`.
2. The plugins of the [preset](#default-plugins).
3. The built-in plugins, which you can't remove: `core:markdown` renders your Markdown collections, `core:pages` serves the data of each page to the browser, and `core:site` adds the title, description and canonical link of each page from your `site` config.

When the site starts, each of these steps runs for every plugin before the next step: `init`, `configureLoader`, loading the content, `configure`, then `routes`. `middleware` and `build` run in plugin order too.

### Merging Results

When several plugins return a value for the same hook, the results combine by hook:

- `head`: tags with a key, like `title`, a `meta` by its `name` or `property`, and the canonical link, are unique. Your `head` option wins over plugins, and an earlier plugin wins over a later one. Other tags are all kept.
- `layoutProps` and `configureLoader`: your own options come first, then plugins in order. Objects merge deeply and lists concatenate, so every plugin can add links. For other values, the first defined value wins.
- `transformPage`: each plugin receives the data so far and adds to it. A field that the page or an earlier plugin has set stays as it is.
- Content hooks, like `getPageBody`: the first result that isn't `undefined` wins, so a plugin returns `undefined` for a page it doesn't render.

`core:site` runs last, so a `title` or `description` tag from any plugin replaces its own.

### Conditional Plugins

`.plugins()` skips `false`, `null` and `undefined`, and flattens lists:

```ts title="press.config.ts"
createPress(content).plugins(process.env.ANALYTICS === "1" && analyticsPlugin(), [
  statusPlugin(),
  changelogPlugin,
]);
```

## Default Plugins

The default preset is `recommendedPreset()`. Each plugin of it has a key in its options:

| Key       | Plugin         | Adds                                                 |
| --------- | -------------- | ---------------------------------------------------- |
| `sitemap` | `core:sitemap` | `/sitemap.xml`                                       |
| `robots`  | `core:robots`  | `/robots.txt`, with a link to the sitemap            |
| `llms`    | `core:llms`    | `/llms.txt` and `/llms-full.txt`, in each language   |
| `search`  | `core:search`  | A search index per language, searched in the browser |

### Configuring a Default Plugin

Pass the options of a default plugin to `recommendedPreset()`, in the `preset` option of `.config()`:

```ts title="press.config.ts"
import { createPress, recommendedPreset } from "@fumapress/vue/config";
import { content } from "@fumapress/vue/content";

export default createPress(content).config({
  preset: recommendedPreset({
    sitemap: { path: "/sitemap-docs.xml" },
    llms: { full: false },
  }),
});
```

The link in `robots.txt` follows the `path` of the sitemap.

### Replacing a Default Plugin

Set the default plugin to `false`, then list your own:

```ts title="press.config.ts"
import { createPress, recommendedPreset } from "@fumapress/vue/config";
import { content } from "@fumapress/vue/content";
import { mySearchPlugin } from "./search-plugin";

export default createPress(content)
  .plugins(mySearchPlugin())
  .config({ preset: recommendedPreset({ search: false }) });
```

The default plugins are exported too, as `sitemapPlugin`, `robotsPlugin`, `llmsPlugin` and `searchPlugin`. To list one yourself, like to run it before another plugin, set it to `false` in the preset first. Otherwise the site has the same plugin twice and fails to start.

### Removing Default Plugins

Set a default plugin to `false` to remove it, or pass an empty list to remove them all:

```ts tab="One plugin" title="press.config.ts"
createPress(content).config({
  preset: recommendedPreset({ llms: false }),
});
```

```ts tab="All plugins" title="press.config.ts"
createPress(content).config({
  preset: [],
});
```

## Plugins From Fumapress for React

The hooks have the names and signatures of `@fumapress/core`, which Fumapress on Waku and Astro use. A plugin that uses only server-side hooks, like routes, middleware, content hooks and `build`, works on both.

The UI is different: the pages of a plugin render with [Vue components of your theme](/plugins/views), and every value sent to the browser is serializable.

## Testing Plugins

`createFetchHandler()` of `@fumapress/vue/server` is the server of a site, without Vite. A test creates a site with your plugin and a custom source, and requests its routes. The handler needs a `render` function for pages, which a test of routes can stub:

```ts title="status-plugin.test.ts"
import { createPress } from "@fumapress/vue/config";
import { createFetchHandler } from "@fumapress/vue/server";
import { expect, test } from "vitest";
import { statusPlugin } from "./status-plugin";

test("answers the status route", async () => {
  const press = createPress({
    files: [{ type: "page", path: "index.md", data: { title: "Home" } }],
  }).plugins(statusPlugin());
  const fetch = createFetchHandler({
    press,
    assets: { css: [], js: [] },
    render: async () => ({ html: "" }),
  });

  const response = await fetch(new Request("http://localhost/api/status"));
  expect(await response.json()).toEqual({ ok: true });
});
```

`@fumapress/vue/content` needs the Vite plugin, so a test lists its files instead of importing `content`.
