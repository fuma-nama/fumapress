---
title: Content Hooks
description: Render the pages of a content source with a plugin.
---

A content source is a list of files: pages and `meta.json` files. The Markdown collections of your site are sources, and the built-in `core:markdown` plugin renders them. A source of your own, from an API, a CMS or a list in code, needs a plugin that renders its pages with content hooks.

This site has a `changelog` source next to its docs. Its pages come from a list in the config, and a plugin renders them:

```ts title="press.config.ts"
import { createPress, type Source } from "@fumapress/vue/config";
import { defineDocs } from "@fumapress/vue/content";

const docs = defineDocs({ dir: "content" });

interface Release {
  title: string;
  description: string;
  date: string;
  html: string;
}

const releases = [
  { version: "0.2.0", date: "2026-11-01", notes: "<p>Custom content sources.</p>" },
  { version: "0.1.0", date: "2026-10-01", notes: "<p>The first release.</p>" },
];

const changelog: Source<{ pageData: Release; metaData: {} }> = {
  files: releases.map(({ version, date, notes }) => ({
    type: "page",
    path: `changelog/${version}.md`,
    data: { title: `v${version}`, description: "Release notes", date, html: notes },
  })),
};

export default createPress({ docs: docs.toFumadocsSource(), changelog }).plugins({
  name: "site:changelog",
  getPageBody(page) {
    if (page.type === "changelog") return { html: page.data.html };
  },
  getPageText(page) {
    if (page.type === "changelog") return `# ${page.data.title}`;
  },
  getPageLastModified(page) {
    if (page.type === "changelog") return new Date(page.data.date);
  },
});
```

The `path` of a file sets the URL of its page, so `changelog/0.2.0.md` is `/changelog/0.2.0`. Its `data` is `page.data`: `title` and `description` are the title and description of the page, and the plugin reads the rest.

With sources by key, `page.type` is the key of the source of a page. A plugin checks it and returns `undefined` for the pages of other sources, since the first result of a content hook wins. A plugin written in `.plugins()` has the types of the site, so `page.type === "changelog"` gives `page.data` the fields of `Release`. With one source, `page.type` is `undefined`. For sources that load files on the server, like from a CMS, see [Content Sources](/content/sources).

## Page Body

`getPageBody` is the only hook a page needs. It returns one of:

- `{ html }`: HTML rendered as it is, as the content of the page.
- `{ view: { type, props } }`: the page has `props` in place of its content. `type` is the key of the source of the page, and the component of [`views`](/theme#page-types) for that key renders it with its own layout, like the component of a [view](/plugins/views).
- `{ module, load }`: the URL of a module that the browser imports, whose default export is the content component, and `load()` to import the same module on the server. This is what `core:markdown` returns for a compiled Markdown file.

```ts
getPageBody(page) {
  if (page.type === "cards") return { view: { type: "cards", props: { title: page.data.title } } };
},
```

A plugin of its own module declares these props in its types, as `pages` by source key, like the [views of a plugin](/plugins/views#views-of-plugins).

A page that no plugin renders fails with an error that names its file.

## Other Content Hooks

Each of these is optional. A page without a result has none of what the hook gives:

- `getPageToc` returns the table of contents, a list of `{ title, url, depth }`, for the docs layout.
- `getPageText` returns the page as Markdown, for `llms-full.txt`.
- `getPageStructuredData` returns the headings of the page and the text under each, for the search index.
- `getPageLastModified` returns a `Date`, for the sitemap and the last update shown on the page.

`getPageStructuredData` returns `headings`, a list of `{ id, content }`, and `contents`, a list of `{ heading, content }` where `heading` is the `id` of the heading a text is under:

```ts
getPageStructuredData(page) {
  if (page.type !== "changelog") return;
  return {
    headings: [],
    contents: [{ content: page.data.html.replace(/<[^>]+>/g, "") }],
  };
},
```

## Page Data

The browser receives the page data of each page, `pageData`: `title`, `description` and `full` from `page.data`, `lastModified` from the `getPageLastModified` hook, then what the `transformPage` hook of each plugin adds. A field that the page or an earlier plugin has set stays as it is.

The docs layout shows `lastModified` as the last update of the page, and `githubUrl` as a link to edit it:

```ts
transformPage(_data, { page }) {
  if (page?.type === "changelog") {
    return { githubUrl: "https://github.com/acme/docs/blob/main/CHANGELOG.md" };
  }
},
```

`transformPage` runs for [views](/plugins/views#page-data) too, where `env.page` is `undefined`. Every value it returns is sent to the browser, so it must be serializable.

## Startup Hooks

Three hooks run once, when the site starts, in this order for all plugins:

1. `init` runs before the content loads, so `this.getPages()` is still empty.
2. `configureLoader` returns options of the Fumadocs content loader, merged with the options you pass to `createPress()`, which win over them. The `plugins` of every plugin are combined, after your `loaderPlugins`.
3. `configure` runs after the content loads, with every page available.

```ts
configure() {
  for (const page of this.getPages()) {
    if (!page.data.title) throw new Error(`${page.path} has no title`);
  }
},
```

A dynamic source is read again with `this.invalidateLoader()`, which doesn't run these hooks again.
