`@fumapress/vue` turns the Markdown files of a folder into a docs site. It is a Vite plugin: Nitro prerenders the pages and serves the rest, and the app navigates between pages without loading a new document.

## What a Site Gets

Add the plugin to `vite.config.ts` and write pages under `content/`. Without other configuration, the site has:

- A docs layout with a sidebar built from your files, a table of contents, and a light and dark theme.
- Markdown and MDX with callouts, highlighted code blocks, tabs, steps and components like `Cards` and `TypeTable`.
- Search in the browser, from an index generated at build time, so it works on a static host.
- `/sitemap.xml`, `/robots.txt`, `/llms.txt` and `/llms-full.txt`.
- Pages prerendered to HTML at build time, with client-side navigation after the first load.

## Files of a Site

Only `vite.config.ts` and the pages are required. The other files are optional, and each runs in its own place:

- `vite.config.ts`: the Vite plugin, with the [compile options of Markdown](/markdown#compile-options) and the [options of Nitro](/deploy#server-deployment). It runs in Vite, on the dev server and in the build.
- `content/`: the [pages](/content) and `meta.json` files, compiled by Vite.
- `press.config.ts`: the [content, site options, plugins and views](/config). It runs on the server only, so it can read secrets.
- `src/theme.ts`: the [theme](/theme), which gives each page type its component and adds Markdown components and icons. It runs on the server and in the browser.
- `src/theme.css`: the [stylesheet](/theme#styles), in place of the default one.
- `src/pages/`: [custom pages](/pages), Vue files that render on the server and in the browser.

## Differences from Fumapress and Fumadocs

`@fumapress/vue` is Fumapress for Vue. Its config and plugins have the shape of [Fumapress](https://press.fumadocs.dev) on React: the same `createPress()` chain, and plugin hooks with the same names and signatures. The UI is a port of [Fumadocs UI](https://fumadocs.dev) to Vue, with the same markup and Tailwind CSS classes. The package bundles the parts of Fumadocs it uses, so a site installs neither Fumadocs nor React.

The differences:

- The UI of a page type is a component in [`views` of the theme](/theme#page-types), where Fumapress has `ui.renderPage` in the config: the config runs on the server only, and a component runs in the browser too.
- A [view](/plugins/views) returns props, and the theme names the component that renders them, since the server can't send a component to the browser.
- A theme builds on the default theme or the base theme only when it names it in `extends`.
- The [layout](/ui#choosing-a-layout) is a component the theme imports, where Fumapress passes `layout` to `renderDefault()`.
- The [compile options](/markdown#compile-options) of Markdown are global, in the Vite plugin, where Fumadocs MDX has them per collection.
- The frontmatter of a collection is [validated when the server starts](/content#frontmatter-schema), not when its file compiles.
- `.views()` of `createPress()` adds the views of your site, without a plugin.
