Each Markdown or MDX file under `content/` is a page, and the sidebar lists them for you.

## Pages

The URL of a page comes from its file path:

| File                          | URL                |
| ----------------------------- | ------------------ |
| `content/index.mdx`           | `/`                |
| `content/getting-started.mdx` | `/getting-started` |
| `content/guide/index.mdx`     | `/guide`           |
| `content/guide/install.md`    | `/guide/install`   |

Files and folders starting with `_` aren't pages, so they can hold [partials](/markdown#partials) next to your pages.

In the dev server, adding, renaming or removing a file updates the sidebar without a restart, and so does a change of frontmatter or of a `meta.json`.

## Collections

A collection is a folder of pages and `meta.json` files. `defineDocs()` in `press.config.ts` defines one, and `toFumadocsSource()` gives its pages to the site. A site without `press.config.ts` has this config:

```ts title="press.config.ts"
import { createPress } from "@fumapress/vue/config";
import { defineDocs } from "@fumapress/vue/content";

const docs = defineDocs({ dir: "content" });

export default createPress(docs.toFumadocsSource());
```

`dir` is the folder from the root of the project, `content/docs` by default. For a second folder, like a blog, see [Multiple Sources](/content/sources#multiple-sources).

`defineDocs()` and `defineCollections()` are macros, like those of [Fumadocs MDX](https://fumadocs.dev/docs/mdx/macro). The Vite plugin reads their calls without running `press.config.ts`, and compiles each call to imports of the files of its folder. So a call follows two rules:

- It is the value of a top-level `const`, like `const docs = defineDocs({ ... })`.
- `dir`, `files`, `type` and `lastModified` are literals, not variables or expressions.

A call that breaks a rule fails with its file, line and column.

### Leaving Files Out

`files` lists the pages of a collection with glob patterns, from `dir`. A pattern starting with `!` leaves files out, so they aren't pages and the build doesn't include them:

```ts title="press.config.ts"
const docs = defineDocs({
  dir: "content",
  docs: { files: ["**/*.{md,mdx}", "!drafts/**"] },
});
```

`meta.files` does the same for the `meta.json` files. Files and folders starting with `_` are in no collection, whatever the patterns.

### Frontmatter Schema

Without a schema, the frontmatter of a page has the fields of [Markdown](/markdown#frontmatter), with `title` required, and `page.data` leaves out other fields. `docs.schema` takes any validator of [Standard Schema](https://standardschema.dev), like Zod or Valibot. `@fumapress/vue/schema` exports `pageSchema` and `metaSchema` of Fumadocs as Zod objects, which need `zod` installed:

```npm
npm i zod
```

```ts title="press.config.ts"
import { createPress } from "@fumapress/vue/config";
import { defineDocs } from "@fumapress/vue/content";
import { pageSchema } from "@fumapress/vue/schema";
import { z } from "zod";

const docs = defineDocs({
  dir: "content",
  docs: { schema: pageSchema.extend({ author: z.string() }) },
});

export default createPress(docs.toFumadocsSource());
```

`page.data.author` is a `string` in plugins and views, without a type annotation. `meta.schema` validates the `meta.json` files the same way.

The server validates every page and `meta.json` when it starts. A file that doesn't match its schema fails the build, and the dev server shows the error, with the file and each of its issues.

## Sidebar

The sidebar lists the pages and folders of the content. Add a `meta.json` to a folder to set its title and the order of its pages:

```json title="content/meta.json"
{
  "pages": ["index", "---Guides---", "guide"]
}
```

```json title="content/guide/meta.json"
{
  "title": "Guide",
  "icon": "BookOpen",
  "defaultOpen": true,
  "pages": ["install", "configure", "..."]
}
```

| Field         | Use                                            |
| ------------- | ---------------------------------------------- |
| `title`       | The name of the folder in the sidebar          |
| `icon`        | The icon of the folder, see [Icons](#icons)    |
| `defaultOpen` | Open the folder in the sidebar by default      |
| `pages`       | The pages and folders of the folder, in order  |
| `root`        | Make the folder a [root folder](#root-folders) |

Items of `pages` are file names without the extension, or folder names. `"..."` adds the pages that aren't listed, and `"---Guides---"` adds a separator with the text "Guides". `"!name"` leaves a page out of `"..."`, so the sidebar doesn't list it, while the page still exists at its URL:

```json title="content/meta.json"
{
  "pages": ["...", "!changelog"]
}
```

For other syntax of `meta.json`, see the [page conventions of Fumadocs](https://fumadocs.dev/docs/page-conventions).

### Root Folders

A folder with `"root": true` is a tab of the sidebar, for separate parts of the docs like a guide and an API reference. On a page in a root folder, the sidebar shows only the content of that folder, and a dropdown at its top switches to the other root folders:

```json title="content/guide/meta.json"
{
  "title": "Guide",
  "root": true
}
```

## Icons

The `icon` of a page or a folder is a name. Map the names to components in the `icons` of the [theme](/theme):

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import { BookOpen, Rocket } from "@lucide/vue";

export default {
  icons: { BookOpen, Rocket },
} satisfies Partial<Theme>;
```

`src/theme.ts` is found by default, and `@lucide/vue` is a package to install. A name without a component is shown as text, so an emoji works as an icon too:

```mdx title="content/index.mdx"
---
title: Introduction
icon: 🚀
---
```
