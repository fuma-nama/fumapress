The theme module is the UI of your site. Create `src/theme.ts` and export the parts you want to change: the rest comes from the default theme.

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import { BookOpen, Rocket } from "@lucide/vue";
import Badge from "./components/Badge.vue";

export default {
  components: { Badge },
  icons: { BookOpen, Rocket },
} satisfies Partial<Theme>;
```

Fumapress picks up `src/theme.ts`, `src/theme.js`, `src/theme/index.ts` or `src/theme/index.js`, in this order. To use another file, set the `theme` option of the Vite plugin:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [press({ theme: "src/docs-theme.ts" })],
});
```

Your theme is merged over the default theme. `components`, `views` and `icons` merge by name, while `Root`, `Layout`, `head` and `enhanceApp` replace the ones of the default theme. The theme module runs on the server and in the browser, so use browser APIs only in `onMounted()` and event handlers.

## Markdown Components

`components` makes components available in Markdown by name, without an import.

```mdx title="content/index.mdx"
<Badge>New</Badge>
```

Markdown uses the `components` of the theme by name, in pages and in the [partials](/markdown#partials) they import. A key that is the name of an element, like `a`, `pre` or `img`, replaces that element, so every link, code block or image of Markdown renders with your component. A component with the name of a default one, like `Callout` or `Card`, replaces it. The default theme registers the components listed in [Components](/ui/components#markdown-components).

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import Image from "./components/Image.vue";

export default {
  components: { img: Image },
} satisfies Partial<Theme>;
```

A component registered with `app.component()` isn't available in Markdown: Markdown reads only `components`.

To load the code of a component only on the pages that use it, wrap it in `defineAsyncComponent()`:

```ts title="src/theme.ts"
import { defineAsyncComponent } from "vue";
import type { Theme } from "@fumapress/vue/client";

export default {
  components: {
    Playground: defineAsyncComponent(() => import("./components/Playground.vue")),
  },
} satisfies Partial<Theme>;
```

## Icons

`icons` are the icons of the sidebar, by the `icon` of a page or a folder:

```json title="content/guide/meta.json"
{
  "title": "Guide",
  "icon": "BookOpen"
}
```

An icon is any Vue component, like the icons of `@lucide/vue`, which you install yourself. An `icon` with no component of that name stays text, so an emoji works too.

## Views

`views` are the components rendering the pages of plugins, by the `type` of their view. Each view renders its own layout. See [Views](/plugins/views).

## Layout

`Layout` renders every content page, every view and the not found page. The default one renders content pages in the [docs layout](/ui). To change it, write your own and read the page with the composables of `@fumapress/vue/client`:

```vue title="src/Layout.vue"
<script setup lang="ts">
import { useLayoutProps, usePage, usePageTree } from "@fumapress/vue/client";
import NotFound from "@fumapress/vue/theme/NotFound.vue";
import { DocsLayout } from "@fumapress/vue/ui/layouts/docs";
import { DocsBody, DocsPage, DocsTitle } from "@fumapress/vue/ui/layouts/docs/page";

const page = usePage();
const tree = usePageTree();
const { nav, links, githubUrl } = useLayoutProps();
</script>

<template>
  <component :is="page.Content" v-if="page?.view" :key="page.url" />
  <DocsLayout v-else-if="page" :tree="tree" :nav="nav" :links="links" :github-url="githubUrl">
    <DocsPage :key="page.url" :toc="page.toc" :full="page.data.full">
      <DocsTitle>{{ page.data.title }}</DocsTitle>
      <DocsBody>
        <component :is="page.Content" />
      </DocsBody>
    </DocsPage>
  </DocsLayout>
  <NotFound v-else />
</template>
```

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import Layout from "./Layout.vue";

export default { Layout } satisfies Partial<Theme>;
```

Your `Layout` handles three cases, like the default one:

- `page.view` is set on the page of a plugin: render `page.Content`, which is the component of the view.
- On a content page, render `page.Content`, the compiled Markdown, inside your layout.
- `page` is `undefined` on a URL without a page: render the not found page.

`page.data` has the `title`, `description` and `full` of the page, the `githubUrl` of its source file, and what plugins add. The composables are:

- `usePage()`: the page on screen, a ref.
- `usePageTree()`: the page tree of the current language.
- `useLayoutProps()`: the [layout props](/config#layout-props) of the site.
- `useSite()`: the `name` and `description` of the site.
- `usePress()`: the state of the app, with the `components` and `views` of the theme.
- `useRouter()`: the router. `route` is a ref of the page on screen, with its `path`, `query`, `hash` and `params`. `push()` and `replace()` navigate, and `resolve(path)?.href` is the URL of a page with the [base path](/deploy#base-path). `enhanceApp` receives the same router.

`Link` from `@fumapress/vue/client` links to a page of the site with client-side navigation, and opens other URLs in a new tab.

To start from the full default layout instead, copy it with the [CLI](/cli): `fumapress-vue add theme`.

## Root

`Root` wraps every page of the app, custom pages too. The default one renders `RootProvider`, which provides search, the light and dark themes, and the language switch. A `Root` of your own wraps the default one to keep those, like in [Search](/search#using-algolia-or-orama-cloud).

## Head and App Setup

`head` adds tags to every page, like a script that runs before the first paint. Your tags come after those of the default theme, which hold the script that applies the color mode before the first paint:

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";

export default {
  head: [{ tag: "script", attrs: { src: "/analytics.js", defer: true } }],
} satisfies Partial<Theme>;
```

For tags that depend on the page, use [`head` in `press.config.ts`](/config#head): its tags win over the theme's by key.

`enhanceApp` receives the Vue `app` and the `router`, to register Vue plugins and the hooks of the router. It runs on the server and in the browser, before the app loads its first page:

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import { createPinia } from "pinia";

export default {
  enhanceApp({ app }) {
    app.use(createPinia());
  },
} satisfies Partial<Theme>;
```

### Router Hooks

`router.beforeEach()` adds a hook that runs before a page shows, and `router.afterEach()` adds a hook that runs after the app moved to another page. Each returns a function that removes the hook.

A `beforeEach` hook returns `false` to cancel the navigation, or a path of the site to go there instead. It runs for the first page too, with `first: true`, and when it sends the first page to another path, the server answers with a redirect:

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";

export default {
  enhanceApp({ router }) {
    // the pages of version 1 moved to /v2
    router.beforeEach((to) => {
      if (to.path.startsWith("/v1/")) return to.path.replace("/v1/", "/v2/");
    });
  },
} satisfies Partial<Theme>;
```

An `afterEach` hook runs in the browser and receives the page the app moved to. It doesn't run for the page the app starts at, which an analytics script counts when it loads, so a hook counts the pages of later navigations:

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import { trackPageView } from "./analytics";

export default {
  enhanceApp({ router }) {
    router.afterEach((to) => trackPageView(to.href));
  },
} satisfies Partial<Theme>;
```

## Custom Pages

A `.vue` file under `src/pages` is a page of your site, at the path of the file:

- `index.vue` is `/`, and `blog/index.vue` is `/blog`.
- `about.vue` is `/about`.
- `blog/[slug].vue` matches one segment, like `/blog/hello`.
- `[...path].vue` matches every URL under its folder.

Files and folders starting with `_` aren't pages, so they can hold the components of your pages.

When a custom page and a content page have the same URL, the more specific one renders. A custom page at a fixed path, like `about.vue`, wins over a content page, and a content page wins over a custom page with params. So `[...path].vue` renders the URLs nothing else has, in place of the not found page. A content page that a custom page replaces stays in the sitemap and the search index, so remove its file.

Pages without params are generated at build time and listed in the sitemap, while pages with params, like `blog/[slug].vue`, render on demand, so they need a [deployment](/deploy) with a server. Read the params with `useRouter()` of `@fumapress/vue/client`: `useRouter().route.value.params.slug`.

To give a custom page the navbar of your site, wrap it in `HomeLayout`:

```vue title="src/pages/about.vue"
<script setup lang="ts">
import HomeLayout from "@fumapress/vue/theme/HomeLayout.vue";
</script>

<template>
  <HomeLayout>
    <main class="mx-auto w-full max-w-(--fd-layout-width) px-4 py-12">
      <h1 class="text-3xl font-semibold">About</h1>
      <p class="text-fd-muted-foreground">We write docs.</p>
    </main>
  </HomeLayout>
</template>
```

A custom page names its title and description with `defineOptions`. They go to the `<head>` like those of a content page, so the title ends with the name of your site:

```vue title="src/pages/about.vue"
<script setup lang="ts">
defineOptions({ page: { title: "About", description: "Who writes these docs." } });
</script>
```

To use another folder, set the `pagesDir` option of the Vite plugin, like `press({ pagesDir: "src/routes" })`.

## Colors

The colors of the UI are CSS variables like `--color-fd-primary`, and each color theme is a stylesheet of the package. To pick another one, create `src/theme.css`. Fumapress loads it in place of the default stylesheet:

```css title="src/theme.css"
@import "@fumapress/vue/style/ocean.css";
```

The color themes are `neutral`, `black`, `vitepress`, `dusk`, `catppuccin`, `ocean`, `purple`, `solar`, `emerald`, `ruby`, `aspen` and `shadcn`. To change single colors, set their variables after the import:

```css title="src/theme.css"
@import "@fumapress/vue/style/neutral.css";

:root {
  --color-fd-primary: hsl(160, 84%, 39%);
}

.dark {
  --color-fd-primary: hsl(158, 64%, 52%);
}
```

## Fonts

The UI uses the font variables `--font-sans` and `--font-mono`. To use another font, load it with `@font-face` in `src/theme.css` and set the variable:

```css title="src/theme.css"
@import "@fumapress/vue/style/neutral.css";

@font-face {
  font-family: "Inter";
  src: url("./fonts/Inter.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap;
}

:root {
  --font-sans: "Inter", sans-serif;
}
```

A `url()` relative to the stylesheet is a file of your project, like `src/fonts/Inter.woff2`, which the build includes.

## Tailwind CSS

The stylesheets above are compiled, so a site needs no Tailwind CSS. The UI is written with Tailwind CSS classes though, and you can use them in your pages and components, or change them in a [copy of the UI](/cli). Install Tailwind CSS and add its Vite plugin:

```npm
npm install -D tailwindcss @tailwindcss/vite
```

```ts title="vite.config.ts"
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [press(), tailwindcss()],
});
```

Then write the stylesheet from its sources: Tailwind CSS, a color theme, and the styles of the UI. Tailwind CSS now generates the classes of the UI together with yours:

```css title="src/theme.css"
@import "tailwindcss";
@import "@fumapress/vue/css/ocean.css";
@import "@fumapress/vue/css/preset.css";
```

## Without the Default Theme

With `defaultTheme: false` in the Vite plugin, your theme doesn't build on the default one: its layout, `Root` and Markdown components aren't in the JavaScript of your site. Your theme module then gives the `Layout`, and a site without a theme module fails to start:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [press({ defaultTheme: false })],
});
```

```ts title="src/theme.ts"
import type { Theme } from "@fumapress/vue/client";
import Layout from "./Layout.vue";
import Note from "./components/Note.vue";

export default {
  Layout,
  components: { Note },
} satisfies Theme;
```

The [stylesheet](#colors) is still the default one until you create `src/theme.css`.

## Vue Plugin Options

The Vite plugin sets up `@vitejs/plugin-vue` for your `.vue` files. Its `vue` option takes the [options of the Vue plugin](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue#options), which are added to the ones Fumapress sets, like the custom elements of your templates:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [
    press({
      vue: {
        template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith("x-") } },
      },
    }),
  ],
});
```
