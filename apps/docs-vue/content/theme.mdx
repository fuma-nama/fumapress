The theme module is the UI of your site. Create `src/theme.ts`, and default-export a theme that builds on the default one:

```ts title="src/theme.ts"
import { BookOpen, Rocket } from "@lucide/vue";
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import type app from "../press.config";
import Badge from "./components/Badge.vue";

export default defineTheme<typeof app>({
  extends: defaultTheme,
  components: { Badge },
  icons: { BookOpen, Rocket },
});
```

`defineTheme<typeof app>()` checks the theme against the pages of your site, with a type-only import of `press.config.ts`. A site without `press.config.ts` calls `defineTheme()` without the type, and a site without TypeScript can do the same in `src/theme.js`.

A site without a theme module uses the default theme. Fumapress picks up `src/theme.ts`, `src/theme.js`, `src/theme/index.ts` or `src/theme/index.js`, in this order. To use another file, set the `theme` option of the Vite plugin:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [press({ theme: "src/docs-theme.ts" })],
});
```

The theme module runs on the server and in the browser, so use browser APIs only in `onMounted()` and event handlers.

## Page Types

The pages of a site have types: the content pages of each source are one type, and the pages of each view another. `views` gives each page type its component, the view component. The keys are:

- The key of a source, for its content pages, like `blog` for the pages of `{ blog: blog.toFumadocsSource() }`.
- The name of a [view](/plugins/views), of `.views()` or of a plugin.
- `default`, for the content pages of a source without a component of its own. The default theme sets it to the docs layout.

A value is a component, or a function that imports it, so only the pages that render it load its code. This theme renders the posts of the `blog` source and the `releases` view with components of its own, and the other content pages with the docs layout of the default theme:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import type app from "../press.config";

export default defineTheme<typeof app>({
  extends: defaultTheme,
  views: {
    blog: () => import("./views/BlogPost.vue"),
    releases: () => import("./views/Releases.vue"),
  },
});
```

A layout is a view component too: [Choosing a Layout](/ui#choosing-a-layout) sets another one for the content pages, or for the pages of one source.

### Typed View Components

A view component receives one prop, `page`. `PageOf<typeof app, "blog">` of `@fumapress/vue/client` is its type, which is what the browser receives for a page of that type. A content page renders its content with `page.Content`:

```vue title="src/views/BlogPost.vue"
<script setup lang="ts">
import type { PageOf } from "@fumapress/vue/client";
import type app from "../../press.config";

defineProps<{ page: PageOf<typeof app, "blog"> }>();
</script>

<template>
  <article>
    <h1>{{ page.pageData.title }}</h1>
    <p>{{ page.data.date }}</p>
    <component :is="page.Content" />
  </article>
</template>
```

The component renders the whole page, so this one has no navbar. Wrap it in the [home layout](/ui#landing-pages) for the navbar of your site, like the components of the [Blog](/content/blog) guide.

A content page has:

- `type`: the key of its source, `undefined` with one source.
- `url`: its path, without the base path.
- `data`: the frontmatter of its file, validated by its [schema](/content#frontmatter-schema), as JSON: a `Date` is a string.
- `pageData`: its `title`, `description` and `full`, the `githubUrl` of its file, its `lastModified` date, and what plugins add with `transformPage`.
- `toc`: its table of contents.
- `Content`: its content, which renders Markdown with the `components` of the theme.

A view has `type`, `url`, `pageData`, and `props`, what its `view` returned. A source whose pages a [plugin renders as views](/plugins/content#page-body) has `props` in place of `Content`, and needs a component under its own key.

With `defineTheme<typeof app>()`, a key that isn't a page type of your site, a component whose `page` is of another type, and a page type without a component are type errors. A page type can get its component from the theme of `extends`, like the theme a plugin ships. A functional component in `views` declares its `props`, since a function without them is read as a function that imports a component.

A page shows once its data, its content and its view component have loaded.

## Markdown Components

`components` makes components available in Markdown by name, without an import.

```mdx title="content/index.mdx"
<Badge>New</Badge>
```

Markdown uses the `components` of the theme by name, in pages and in the [partials](/markdown#partials) they import. A key that is the name of an element, like `a`, `pre` or `img`, replaces that element, so every link, code block or image of Markdown renders with your component. A component with the name of a default one, like `Callout` or `Card`, replaces it. The default theme registers the components listed in [Components](/ui/components#markdown-components).

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import Image from "./components/Image.vue";

export default defineTheme({
  extends: defaultTheme,
  components: { img: Image },
});
```

A component registered with `app.component()` isn't available in Markdown: Markdown reads only `components`.

To load the code of a component only on the pages that use it, wrap it in `defineAsyncComponent()`:

```ts title="src/theme.ts"
import { defineAsyncComponent } from "vue";
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";

export default defineTheme({
  extends: defaultTheme,
  components: {
    Playground: defineAsyncComponent(() => import("./components/Playground.vue")),
  },
});
```

## Icons

`icons` maps the `icon` names of pages and folders to Vue components, like the icons of `@lucide/vue`. See [Icons](/content#icons) of the content.

## Building on Other Themes

A theme is used as written: it has the UI of the default theme because it names the default theme in `extends`. `extends` takes a theme or a list of themes, where a later theme wins over an earlier one. Your theme adds to them:

- `views`, `components` and `icons` merge by name, and your entries win.
- `head` lists are joined, with your tags last.
- The `enhanceApp` of each theme runs, yours last.
- `Root` and `NotFound` replace theirs.

There are two themes to build on:

- The default theme, `@fumapress/vue/theme/default`, renders content pages with the docs layout.
- The base theme, `baseTheme` of `@fumapress/vue/theme`, is the default theme without a layout for content pages: its `Root`, `NotFound`, Markdown components and the script of the color mode. A theme with [another layout](/ui#choosing-a-layout) extends it, so the code of the docs layout isn't in your site.

To change the default theme beyond its options, copy it into your project with the [CLI](/cli): `npx @fumapress/vue-cli add theme`.

### A Theme Without `extends`

A theme without `extends` doesn't build on the default theme: its layouts, `Root` and Markdown components aren't in the JavaScript of your site. Your theme then gives a component for every page type, with `views.default` for content pages, and `NotFound` for a URL without a page:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import type app from "../press.config";
import NotFound from "./NotFound.vue";
import Page from "./Page.vue";
import Note from "./components/Note.vue";

export default defineTheme<typeof app>({
  NotFound,
  views: { default: Page },
  components: { Note },
});
```

A page without a component fails to render, and so does a URL without a page when the theme has no `NotFound`, with an error that names what is missing. The build renders `404.html`, so it fails without `NotFound`.

The [stylesheet](#styles) is still the default one until you create `src/theme.css`.

## Root

`Root` wraps every page of the app, custom pages too. The default one renders `RootProvider`, which provides search, the light and dark themes, and the language switch. A `Root` of your own wraps the default one to keep those, like in [Search](/search#using-algolia-or-orama-cloud).

## Head and App Setup

`head` adds tags to every page, like a script that runs before the first paint. Your tags come after those of the default theme, which hold the script that applies the color mode before the first paint:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";

export default defineTheme({
  extends: defaultTheme,
  head: [{ tag: "script", attrs: { src: "/analytics.js", defer: true } }],
});
```

For tags that depend on the page, use [`head` in `press.config.ts`](/config#head): its tags win over the theme's by key.

`enhanceApp` receives the Vue `app` and the `router`, to register Vue plugins and the hooks of the router. It runs on the server and in the browser, before the app loads its first page:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import { createPinia } from "pinia";

export default defineTheme({
  extends: defaultTheme,
  enhanceApp({ app }) {
    app.use(createPinia());
  },
});
```

### Router Hooks

`router.beforeEach()` adds a hook that runs before a page shows, and `router.afterEach()` adds a hook that runs after the app moved to another page. Each returns a function that removes the hook.

A `beforeEach` hook returns `false` to cancel the navigation, or a path of the site to go there instead. It runs for the first page too, with `first: true`, and when it sends the first page to another path, the server answers with a redirect:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";

export default defineTheme({
  extends: defaultTheme,
  enhanceApp({ router }) {
    // the pages of version 1 moved to /v2
    router.beforeEach((to) => {
      if (to.path.startsWith("/v1/")) return to.path.replace("/v1/", "/v2/");
    });
  },
});
```

An `afterEach` hook runs in the browser and receives the page the app moved to. It doesn't run for the page the app starts at, which an analytics script counts when it loads, so a hook counts the pages of later navigations:

```ts title="src/theme.ts"
import { defineTheme } from "@fumapress/vue/theme";
import defaultTheme from "@fumapress/vue/theme/default";
import { trackPageView } from "./analytics";

export default defineTheme({
  extends: defaultTheme,
  enhanceApp({ router }) {
    router.afterEach((to) => trackPageView(to.href));
  },
});
```

## Styles

The stylesheet of your site is `src/theme.css`, or `src/theme/style.css`, when the file exists. It replaces the default stylesheet, and it is loaded with or without a theme module.

### Colors

The colors of the UI are CSS variables like `--color-fd-primary`, and each color theme is a stylesheet of the package. To pick another one, import it in `src/theme.css`:

```css title="src/theme.css"
@import "@fumapress/vue/style/ocean.css";
```

The color themes are `neutral`, `black`, `vitepress`, `dusk`, `catppuccin`, `ocean`, `purple`, `solar`, `emerald`, `ruby`, `aspen` and `shadcn`. To change single colors, set their variables after the import:

```css title="src/theme.css"
@import "@fumapress/vue/style/neutral.css";

:root {
  --color-fd-primary: hsl(160, 84%, 39%);
}

.dark {
  --color-fd-primary: hsl(158, 64%, 52%);
}
```

### Fonts

The UI uses the font variables `--font-sans` and `--font-mono`. To use another font, load it with `@font-face` in `src/theme.css` and set the variable:

```css title="src/theme.css"
@import "@fumapress/vue/style/neutral.css";

@font-face {
  font-family: "Inter";
  src: url("./fonts/Inter.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap;
}

:root {
  --font-sans: "Inter", sans-serif;
}
```

A `url()` relative to the stylesheet is a file of your project, like `src/fonts/Inter.woff2`, which the build includes.

### Tailwind CSS

The stylesheets above are compiled, so a site needs no Tailwind CSS. They have the classes that the UI uses, and only those. To use other classes in your pages and components, or in a [copy of the UI](/cli), install Tailwind CSS and add its Vite plugin:

```npm
npm install -D tailwindcss @tailwindcss/vite
```

```ts title="vite.config.ts"
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";
import press from "@fumapress/vue/vite";

export default defineConfig({
  plugins: [press(), tailwindcss()],
});
```

Then write the stylesheet from its sources: Tailwind CSS, a color theme, and the styles of the UI. Tailwind CSS now generates the classes of the UI together with yours:

```css title="src/theme.css"
@import "tailwindcss";
@import "@fumapress/vue/css/ocean.css";
@import "@fumapress/vue/css/preset.css";
```
