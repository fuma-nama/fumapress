<section id="why">

Fumapress has no built-in login. You check the session in plugin middleware, which runs first on every request your server receives.

</section>

<section id="check">

`getSession()` stands for your own session check. Add this plugin first, so that its middleware wraps the others.

```tsx title="press.config.tsx"
createPress(content).plugins({
  name: "site:auth",
  async middleware(request, next) {
    const session = await getSession(request);
    if (!session) return new Response("Unauthorized", { status: 401 });

    return next();
  },
});
```

Now every page, and every file generated from your content, like `/llms.txt`, requires a session.

</section>

<section id="rest">

Follow the first step of [Protecting the Whole Site](#protecting-the-whole-site), then check in your middleware that the URL starts with the prefix. This check also covers client navigations and `<page>.md`.

```tsx title="press.config.tsx"
createPress(content).plugins({
  name: "site:auth",
  async middleware(request, next) {
    const { pathname } = new URL(request.url);
    const session = await getSession(request);

    const isInternal =
      pathname.startsWith(this.withBase("/internal")) || pathname === this.withBase("/internal.md");

    if (isInternal && !session) return new Response("Unauthorized", { status: 401 });
    return next();
  },
});
```

With [internationalization](./internationalization.mdx), the language prefix comes first, like `/zh/internal`.

URLs like `//internal` and `/%69nternal` redirect to `/internal` first, so your check only sees `/internal`.

</section>

<section id="generated">

### Generated Routes

Plugins also serve your content at paths outside the prefix. For each route below, check its path in the same middleware, exclude the section with the options of the plugin, or remove the plugin.

| Route                         | Plugin                                                           |
| ----------------------------- | ---------------------------------------------------------------- |
| `/llms.txt`, `/llms-full.txt` | [llms.txt](./plugins/ai.mdx#llmstxt)                             |
| `/api/search`                 | [Search](./search.mdx)                                           |
| `/_takumi/...`                | [Open Graph images](./plugins/seo.mdx#open-graph-images)         |
| `/sitemap.xml`                | [Sitemap](./plugins/seo.mdx#sitemap)                             |
| `/rss.xml`                    | [RSS](./plugins/seo.mdx#rss)                                     |
| `/api/ai`, `/mcp`             | [AI chat](./plugins/ai.mdx#ai-chat), [MCP](./plugins/ai.mdx#mcp) |

### Hiding Pages from the Sidebar

Middleware blocks a page, but its link stays in the sidebar. Remove the folder from the page tree, the data behind the sidebar:

```tsx title="press.config.tsx"
createPress(content, {
  pageTree: {
    transformers: [
      {
        root(node) {
          return {
            ...node,
            children: node.children.filter((item) => item.name !== "Internal"), // [!code highlight]
          };
        },
      },
    ],
  },
});
```

The tree is the same for every reader, so the section is hidden from everyone, signed in or not.

</section>
