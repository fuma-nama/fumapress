## Overview

`press.config.tsx` has three stages: content, plugins, then config.

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { metaSchema, pageSchema } from "fumapress/schema";
import { defineDocs } from "fumadocs-mdx/macro";
import { lucideIconsPlugin } from "fumadocs-core/source/plugins/lucide-icons";
import { llmsPlugin } from "fumapress/plugins/llms.txt";
import { blogPlugin } from "@fumapress/blog";
import { blogPageSchema } from "@fumapress/blog/schema";
import { baseOptions, renderPage } from "./src/ui/layout";

const docs = defineDocs({
  dir: "content/docs",
  docs: { async: true, lastModified: true, schema: pageSchema },
  meta: { schema: metaSchema },
});
const blog = defineDocs({
  dir: "content/blog",
  docs: { schema: blogPageSchema },
});

// 1. content and loader options
export const app = createPress(
  {
    docs: docs.toFumadocsSource({ baseDir: "docs" }),
    blog: blog.toFumadocsSource({ baseDir: "blog" }),
  },
  { loaderOptions: { plugins: [lucideIconsPlugin()] } },
)
  // 2. plugins
  .plugins(llmsPlugin({ routes: "all" }), blogPlugin({ source: "blog" }));

// 3. config
export default app.config({
  site: {
    name: "Acme",
    baseUrl: "https://docs.acme.dev",
    git: { user: "acme", repo: "docs", branch: "main" },
  },
  head: [{ tag: "link", attrs: { rel: "icon", href: "/favicon.ico" } }],
  ui: { baseOptions, renderPage },
});
```

`createPress(content, options)` takes your sources and returns a builder. `.plugins(...)` adds plugins (called once; lists are flattened and falsy values skipped). `.config({...})` sets everything else and is the default export.

## Content

The first argument is one source or a record of named sources. The keys become the `type` of each page.

```tsx title="press.config.tsx"
export default createPress(docs.toFumadocsSource()).config({
  // ...
});

// or several sources
export default createPress({
  docs: docs.toFumadocsSource({ baseDir: "docs" }),
  blog: blog.toFumadocsSource({ baseDir: "blog" }),
}).config({
  // ...
});
```

See [Collections](/docs/collections) for defining content sources with Fumadocs MDX.

The optional second argument takes `i18n` (see [Internationalization](/docs/internationalization)) and `loaderOptions`.

### Loader Options

`loaderOptions` configures the [Loader API](https://fumadocs.dev/docs/headless/source-api) that Fumapress creates from your content sources. A common use is loader plugins, such as resolving the `icon` frontmatter field to Lucide icons:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { lucideIconsPlugin } from "fumadocs-core/source/plugins/lucide-icons";

export default createPress(docs.toFumadocsSource(), {
  // [!code ++:3]
  loaderOptions: {
    plugins: [lucideIconsPlugin()],
  },
}).config({
  // ...
});
```

For dynamic content sources (e.g. a CMS), `alwaysRevalidate: true` refetches them on every request:

```tsx title="press.config.tsx"
createPress(docs.toFumadocsSource(), {
  loaderOptions: {
    alwaysRevalidate: true,
  },
});
```

Leave it disabled to control this yourself with `getPressContext<typeof app>().revalidateLoader()`.

## Plugins

`.plugins(a, b)` adds plugins to the site. Call it once between `createPress()` and `.config()`. See [Plugins](/docs/plugins).

## Config

### Site

The site information like name and linked git repository:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";

export default createPress(/* ... */).config({
  site: {
    name: "Fumapress",
    baseUrl: import.meta.env.DEV ? "http://localhost:3000" : "https://press.fumadocs.dev",
    git: {
      user: "fuma-nama",
      branch: "dev",
      repo: "fumapress",
    },
  },
});
```

The repository adds an icon link to the navbar and a link to the source file of each page.

Source file links resolve against the detected git root. Set `git.rootDir` to override it, such as when building without the `.git` directory.

#### URLs

`baseUrl` is required for some features to know the absolute URL of a page.

Page URLs have no trailing slash. The [deployment adapters](/docs/deployment) configure hosts to serve them that way.

#### Locales

With [i18n](/docs/internationalization), every page links its translations with `hreflang`. Locale codes are used as is. Map the ones that are not BCP 47 language tags:

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  site: {
    hreflang: {
      cn: "zh-Hans",
      tw: "zh-Hant",
    },
  },
});
```

#### Git Providers

`git.provider` supports `github` (default), `gitlab` and `bitbucket`. The navbar icon link and source file URLs follow the given provider. For self-hosted instances, pass the instance URL with `git.url`:

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  site: {
    git: {
      provider: "gitlab",
      url: "https://gitlab.example.com",
      user: "fuma-nama",
      branch: "dev",
      repo: "fumapress",
    },
  },
});
```

### Render Mode

`mode` controls how routes are rendered:

- `default`: pages are prerendered. API routes such as the search endpoint run on a server.
- `static`: only static files are emitted, for any static host or CDN.
- `dynamic`: pages render on request, for content sources that change after the build.

```ts title="press.config.tsx"
createPress(/* ... */).config({
  // [!code ++]
  mode: "static",
});
```

See [Deployment](/docs/deployment) for hosting each mode.

### Preset

By default, Fumapress adds recommended plugins automatically:

- [Sitemap](/docs/plugins/sitemap)
- [robots.txt](/docs/plugins/robots)
- [llms.txt](/docs/plugins/llms.txt)
- [RSS](/docs/plugins/rss)
- Search with [FlexSearch](/docs/plugins/flexsearch)
- OG images with [Takumi](/docs/plugins/takumi)
- [Image optimization](/docs/plugins/image) matching your deployment target (Waku only)

Listing a plugin that provides the same [capability](/docs/plugins#capabilities) as a preset entry takes that entry's place. For example, adding `oramaSearchPlugin()` replaces the default search.

To start from an empty plugin list:

```ts title="press.config.tsx"
createPress(/* ... */).config({
  // [!code ++]
  preset: [],
});
```

To drop a single entry, filter by `provides`:

```tsx title="press.config.tsx"
import { createPress, recommendedPreset } from "fumapress";

export default createPress(/* ... */).config({
  preset: recommendedPreset().filter((entry) => entry.provides !== "rss"),
});
```

### Head

Head tags are an array of `{ tag, attrs, children }` entries, such as the favicon and fonts:

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  head: [
    { tag: "link", attrs: { rel: "icon", href: "/favicon.ico" } },
    { tag: "link", attrs: { rel: "preconnect", href: "https://fonts.googleapis.com" } },
    {
      tag: "link",
      attrs: { rel: "preconnect", href: "https://fonts.gstatic.com", crossorigin: "" },
    },
    {
      tag: "link",
      attrs: {
        rel: "stylesheet",
        href: "https://fonts.googleapis.com/css2?family=Geist:ital,wght@0,100..900;1,100..900&family=JetBrains+Mono:ital,wght@0,100..800;1,100..800&display=swap",
      },
    },
  ],
});
```

The function form runs once site-wide (without `page` and `route`) and once per page, with `{ page, route, path, view }`. The site's tags win over the plugins' by key.

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  head({ page }) {
    if (page) return;
    return [{ tag: "link", attrs: { rel: "icon", href: this.withBase("/favicon.ico") } }];
  },
});
```

### UI

#### `baseOptions`

The base layout options shared by every page: navbar, links, and other [Fumadocs layout props](https://fumadocs.dev/docs/ui/layouts/docs). Pass an object, or a function that receives `{ lang }` with `this` as the site context.

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  ui: {
    baseOptions: {
      nav: { title: "My Docs" },
      links: [{ text: "GitHub", url: "https://github.com/acme/docs" }],
    },
  },
});
```

With i18n, use a function to localize paths:

```tsx title="src/ui/layout.tsx"
import type { UIOptions } from "fumapress";
import type { app } from "../press.config";

export const baseOptions: UIOptions<typeof app>["baseOptions"] = function ({ lang }) {
  return {
    links: [{ url: this.localizePath(lang, "/blog"), text: lang === "zh" ? "部落格" : "Blog" }],
  };
};
```

See [Base Options](/docs/layouts#base-options).

#### `providerProps`

Props passed to the root provider of every page, such as the theme. Search plugins put their dialog here automatically. To replace the dialog, pass `search.SearchDialog`. See [Custom Dialog](/docs/search#custom-dialog).

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  ui: {
    providerProps: {
      theme: { defaultTheme: "dark" },
    },
  },
});
```

#### `translations`

UI string translations. See [Translations](/docs/internationalization#translations).

#### `renderPage`

The function that renders every page. See [Render Page](/docs/layouts#render-page).

#### `renderRoot`

Waku only. Replaces the `<html>` document. Render `{head}` inside `<head>` and `{children}` inside `<body>`:

```tsx title="press.config.tsx"
createPress(/* ... */).config({
  ui: {
    renderRoot({ lang, head, children }) {
      return (
        <html lang={lang ?? "en"} className="dark" suppressHydrationWarning>
          <head>{head}</head>
          <body className="antialiased">{children}</body>
        </html>
      );
    },
  },
});
```

## Types

Export the `app` value (the result of `.plugins()`) and use `typeof app` for type helpers:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";

export const app = createPress(/* ... */).plugins(/* ... */);
export default app.config({/* ... */});
```

```tsx title="src/ui/layout.tsx"
import type { RenderPageProps } from "fumapress";
import type { app } from "../press.config";

export function renderPage(props: RenderPageProps<typeof app>) {
  // ...
}
```

Available type helpers from `fumapress`:

- `RenderPageProps<typeof app, "docs">`: props of `ui.renderPage`, narrowed by source or view type.
- `PressContext<typeof app>`: the return type of `getPressContext<typeof app>()`.
- `UIOptions<typeof app>["baseOptions"]`: the type of `ui.baseOptions`.
- `BaseOptions`: the Fumadocs layout props type.
- `ProviderProps`: the root provider props type.
- `WakuRouteProps<typeof app, "/showcase/[slug]">`: props of your own pages, typed by the file path.
- `WakuRouteConfig`: the `getConfig()` return type of route files.

## Styles

### Tailwind CSS

Create a `src/app.css` file:

```css title="src/app.css"
@import "tailwindcss";
@import "fumadocs-ui/css/neutral.css";
@import "fumadocs-ui/css/preset.css";
@import "fumapress/css/preset.css";
```

It is loaded automatically. Restart the dev server if one is running.

You can change the color theme or add custom styles:

```css title="src/app.css"
@import "tailwindcss";
/* [!code --] */
@import "fumadocs-ui/css/neutral.css";
/* [!code ++] */
@import "fumadocs-ui/css/black.css";
@import "fumadocs-ui/css/preset.css";
@import "fumapress/css/preset.css";

@theme {
  /* [!code ++] */
  --default-font-family: "Geist", sans-serif;
}
```

### Using Radix UI

Fumapress uses the [Base UI](https://base-ui.com) headless component library by default, same as Fumadocs.
If you are using [Radix UI](https://radix-ui.com), Fumapress also supports the [Radix UI build of Fumadocs UI](https://fumadocs.dev/docs/ui/component-library).

You can enable it by installing `fumadocs-ui` without the `@fumadocs/base-ui` alias:

```npm
npm i fumadocs-ui
npm uninstall @base-ui/react
```

## Vite Plugin

Waku only. The `press()` plugin connects Fumapress to Vite:

```ts tab="vite.config.ts"
import { defineConfig } from "vite";
import press from "fumapress/vite";
import { fumadocsMdx } from "fumadocs-mdx/vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [press({ components: "./src/components/mdx.tsx" }), fumadocsMdx(), tailwindcss()],
});
```

```tsx tab="src/components/mdx.tsx"
import defaultMdxComponents from "fumadocs-ui/mdx";
import { Callout } from "fumadocs-ui/components/callout";
import type { MDXComponents } from "mdx/types";

export default { ...defaultMdxComponents, Callout } satisfies MDXComponents;
```

The `components` option points to a module whose default export is the MDX components. Relative links between pages resolve automatically.

### Deployment Adapter

Vercel, Netlify and Cloudflare are detected from the environment. Other targets fall back to `waku/adapters/node`. Set `adapter` when the detected one is not what you deploy to. See [Deployment](/docs/deployment).

```ts title="vite.config.ts"
export default defineConfig({
  plugins: [
    press({
      // [!code ++]
      adapter: "waku/adapters/vercel",
    }),
  ],
});
```

## CLI

Waku only. The `fumapress` CLI runs Vite with the environments your site needs. Use it instead of calling `vite` directly.

```json title="package.json"
{
  "scripts": {
    "dev": "fumapress dev",
    "build": "fumapress build",
    "start": "fumapress start"
  }
}
```

`dev` and `start` accept `--host` (`-h`) and `--port` (`-p`). The `PORT` environment variable also sets the port. `dev` listens on port 3000, `start` picks a free port from 8080.

```npm
npm run dev -- --port 4000
```

## Server Entry

Waku only. The server entry file is optional. Create one for a custom router or non-standard rendering.

Custom server entries use [Waku.js](https://waku.gg) APIs directly. Since Fumapress manages Waku as its own dependency, install it explicitly for direct API access, matching the version pinned by Fumapress:

```npm
npm i waku@1.0.0-rc.1
```

```tsx title="src/waku.server.tsx"
import _adapter from "waku/adapters/default";
import press from "../press.config";
import { createRouter } from "fumapress/router";
import { fsRouterFn } from "fumapress/router/fs";
import mdxPlugin from "fumadocs-mdx/press";
import components from "./components/mdx";

const router = await createRouter(press, {
  renderers: [mdxPlugin({ components })],
});

import.meta.hot?.dispose(router.dispose);

const modules = import.meta.glob("./pages/**/*.{ts,tsx,js,jsx}", {
  base: "/src",
});

const pages = router.createPages(fsRouterFn(modules));
const middlewareFns = router.createMiddlewares();
const adapter = router.patchAdapter(_adapter);

export default adapter(pages, { middlewareFns });
```

You can also use [Waku Config-based Routing](https://waku.gg/#routing) instead of the file-system router. The callback takes `(fns)` with `createPage`, `createLayout` and other functions:

```tsx title="src/waku.server.tsx"
import _adapter from "waku/adapters/default";
import press from "../press.config";
import { createRouter } from "fumapress/router";
import mdxPlugin from "fumadocs-mdx/press";
import components from "./components/mdx";

const router = await createRouter(press, {
  renderers: [mdxPlugin({ components })],
});

import.meta.hot?.dispose(router.dispose);

const pages = router.createPages(({ createPage }) => {
  // note: root element is already created by Fumapress
  createPage({
    render: "static",
    path: "/hello-world",
    component() {
      // ...
    },
  });
});

const middlewareFns = router.createMiddlewares();
const adapter = router.patchAdapter(_adapter);

export default adapter(pages, { middlewareFns });
```
