## Overview

`createPress` accepts a single source, or a record of named sources to host several collections on one site:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { defineDocs } from "fumadocs-mdx/macro";
import { pageSchema, metaSchema } from "fumapress/schema";
import { blogPlugin } from "@fumapress/blog";
import { blogPageSchema } from "@fumapress/blog/schema";

const docs = defineDocs({
  dir: "content/docs",
  docs: { async: true, schema: pageSchema },
  meta: { schema: metaSchema },
});

const blog = defineDocs({
  dir: "content/blog",
  docs: { schema: blogPageSchema },
});

export const app = createPress({
  docs: docs.toFumadocsSource({ baseDir: "docs" }),
  blog: blog.toFumadocsSource({ baseDir: "blog" }),
}).plugins(blogPlugin({ source: "blog" }));

export default app.config({ site: { name: "Acme" } });
```

`baseDir` places each collection under its own URL prefix:

| File                     | URL           |
| ------------------------ | ------------- |
| `content/docs/index.mdx` | `/docs`       |
| `content/blog/hello.mdx` | `/blog/hello` |

The record keys become `props.type` in `renderPage`, so code can tell which collection a page belongs to. A plugin owns sources through its `source` option: `blogPlugin({ source: "blog" })` claims the `blog` source, and several sources share a plugin with `source: ["blog", "news"]`.

## Layout per Collection

Switch on `props.type` in `renderPage` to render each collection with a different layout:

```tsx title="src/ui/layout.tsx"
import type { RenderPageProps } from "fumapress";
import type { app } from "../press.config";

function Guide({ page, body }: RenderPageProps<typeof app, "guides">) {
  return (
    <article>
      <span>{page.data.level}</span>
      {body}
    </article>
  );
}

export function renderPage(props: RenderPageProps<typeof app>) {
  const { renderDefault } = props;
  switch (props.type) {
    case "guides":
      return <Guide {...props} />;
    case "blog":
    case "news":
      return (
        <main>
          {props.post.authors.length} authors
          {props.children}
        </main>
      );
    default:
      return renderDefault();
  }
}
```

Pages of a plugin's source arrive with that plugin's props. In the example above, `props.post` is typed by the blog plugin on both the `"blog"` and `"news"` cases. Typed frontmatter like `page.data.level` is available when the source's schema defines it.

## Sidebar

All sources merge into a single page tree, with each `baseDir` as a top-level folder. Mark a collection's folder as a root folder so the sidebar shows only its own pages while browsing it:

```json title="content/docs/meta.json"
{
  "title": "Documentation",
  "root": true,
  "pages": ["..."]
}
```

See [Page Tree](https://fumadocs.dev/docs/page-conventions) for root folders and other conventions.

To scope the sidebar to one collection in your layout, pass its `baseDir` to `selectTreeRoot`:

```tsx
import { selectTreeRoot } from "fumapress";

<DocsLayout {...baseOptions} tree={selectTreeRoot(tree, "docs")}>
```

See [Sidebar](/docs/layouts/docs#sidebar) for details.
