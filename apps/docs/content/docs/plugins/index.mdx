## Overview

Plugins allow you to customize Fumapress and encapsulate the complexity into a plugin.

The hooks of `Plugin` from `@fumapress/core` run on [Waku](/docs) and [Astro](/docs/astro):

```tsx title="my-plugin.tsx"
import type { AppShape, Plugin } from "@fumapress/core";

function Footer() {
  return <p>Hello World</p>;
}

export function myPlugin<C extends AppShape = AppShape>(): Plugin<C> {
  return {
    name: "my-plugin",
    // API routes
    routes() {
      return [
        {
          path: "/api/hello-world",
          render: "dynamic",
          POST: () => new Response("I love Fumapress"),
        },
      ];
    },
    // tags in `<head>`, of content pages with `page`
    head({ page }) {
      if (page) return [{ tag: "meta", attrs: { name: "author", content: "Fuma" } }];
    },
    // UI on content pages
    slots() {
      return [{ slot: "page.footer", component: Footer }];
    },
  };
}
```

`this` in hooks is the app context, with the content loader and the resolved config. Other hooks transform page data (`transformPage`), render the pages of a content source (`getPageBody`, `getPageText`, ...), and check the built site (`build`).

A plugin providing a capability, like `provides: ["search"]`, exposes its API: `this.getProvider("search")?.api` is typed by `CapabilityAPI`.

On Waku, use `PressPlugin` and `AppShape` of `fumapress` in place of the `@fumapress/core` types: `PressPlugin` has these hooks too, with the [Waku hooks](#waku-hooks) on top.

## Views

A route with a `view` is a page in the home layout of the site, like a changelog. `view()` returns its content, with the title and description of the page:

```tsx title="my-plugin.tsx"
import type { AppShape, Plugin, ViewRoute } from "@fumapress/core";

export function changelogPlugin<C extends AppShape = AppShape>(): Plugin<C> {
  return {
    name: "changelog",
    routes() {
      const routes: ViewRoute[] = [];
      for (const lang of this.i18nConfig?.languages ?? [undefined]) {
        routes.push({
          path: "/changelog",
          lang,
          view: () => ({ title: "Changelog", node: <p>Releases in {lang}</p> }),
        });
      }
      return routes;
    },
  };
}
```

The site prefixes `path` with the language of `lang`, and links the pages of other languages at the same `path` as translations. Like API routes, static pages list their params in `staticPaths`. `view()` returns `undefined` for a 404.

To render a content page in the home layout, like a blog post, return it from `getPageView()`:

```tsx title="my-plugin.tsx"
import type { AppShape, Plugin } from "@fumapress/core";

function Post({ title }: { title?: string }) {
  return <h1>{title}</h1>;
}

export function blogPlugin<C extends AppShape = AppShape>(): Plugin<C> {
  return {
    name: "blog",
    getPageView(page) {
      if (page.type === "blog") return { node: <Post title={page.data.title} /> };
    },
  };
}
```

The page keeps its head. Its view replaces the layout of docs pages, the `renderPage` of your config on Waku and your `page` module on Astro.

## Slots

`slots()` adds UI to the layouts: `page.actions`, `page.footer` and `body.wrapper` of content pages with `page`, and `layout.wrapper` around the layout of every page, without `page`:

```tsx title="my-plugin.tsx"
import type { AppShape, Plugin } from "@fumapress/core";
import type { ReactNode } from "react";

function Banner({ children }: { children: ReactNode }) {
  return (
    <>
      <p>We are hiring!</p>
      {children}
    </>
  );
}

export function bannerPlugin<C extends AppShape = AppShape>(): Plugin<C> {
  return {
    name: "banner",
    slots({ page }) {
      if (!page) return [{ slot: "layout.wrapper", component: Banner }];
    },
  };
}
```

Wrappers receive what they wrap as `children`. On Astro, client components hydrate with their `props`, which must be serializable.

## Middlewares

Plugins can add a `middleware()`, which runs before routes on the server. For example, redirecting legacy URLs:

```tsx title="my-plugin.tsx"
import type { AppShape, Plugin } from "@fumapress/core";

export function redirectsPlugin<C extends AppShape = AppShape>(
  redirects: Record<string, string>,
): Plugin<C> {
  return {
    name: "redirects",
    async middleware(request, next) {
      const to = redirects[new URL(request.url).pathname];
      if (to) return Response.redirect(new URL(to, request.url), 308);

      return next();
    },
  };
}
```

Call `next(path)` to serve another path instead. Middlewares require a server, they don't apply to a static deployment.

On Waku, client navigations run them too, with the request of the page: their redirects and rewrites reach the client router.

## Waku Hooks

On Waku, `PressPlugin` adds hooks for its router and layouts, like `createPages()` and `createMiddlewares()` for [Hono](https://hono.dev) middlewares:

```tsx title="my-plugin.tsx"
import type { AppShape, PressPlugin } from "fumapress";

export function myPlugin<C extends AppShape = AppShape>(): PressPlugin<C> {
  return {
    init() {
      // access internal hooks
      this.data["core:docs-layout"] ??= {};
      const transformers = (this.data["core:docs-layout"].transformers ??= []);
      transformers.push(({ data }) => {
        // add element below page body
        data.body = (
          <>
            {data.body}
            <div>Hello World</div>
          </>
        );
        return data;
      });
    },
    createPages({ createApi }) {
      // customize router
      createApi({
        path: "/api/hello-world",
        render: "dynamic",
        handlers: {
          POST: async (req) => {
            console.log(req);
            return new Response("I love Fumapress");
          },
        },
      });
    },
  };
}
```

Plugins using them are Waku only.
