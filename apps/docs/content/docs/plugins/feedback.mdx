## Installation

```npm
npm i @fumapress/feedback
```

Add the plugin:

```tsx title="press.config.tsx"
import { defineConfig } from "fumapress";
// [!code ++]
import { feedbackPlugin } from "@fumapress/feedback";

export default defineConfig({
  // ...
})
  // [!code highlight:10]
  .plugins(
    feedbackPlugin({
      async onPageFeedbackAction(data) {
        // ...
      },
      async onTextFeedbackAction(data) {
        // ...
      },
    }),
  );
```

It works on [Astro](/docs/astro) too, in the `plugins` of `@fumapress/astro/config`.

The `onPageFeedbackAction` & `onTextFeedbackAction` options receive the user feedback on the server, at `/api/feedback/page` and `/api/feedback/text`. These routes need a server, so they are not compatible with `mode: "static"`. You can define the flow afterwards (e.g. storing that in your analytics platform):

```tsx title="press.config.tsx"
feedbackPlugin({
  async onPageFeedbackAction({ opinion, url, message }) {
    await analytics.track("page-feedback", { opinion, url, message });
    return {};
  },
  async onTextFeedbackAction({ url, blockId, blockBody, message }) {
    const discussion = await createDiscussion({ url, blockId, blockBody, message });
    return { githubUrl: discussion.url };
  },
});
```

To send feedback from the browser instead, like to the API of an analytics service, export the action from a `'use client'` module. It runs without routes, so it works with `mode: "static"`:

```ts tab="lib/feedback.ts"
"use client";
import type { PageFeedback } from "@fumapress/feedback/schema";

export async function onPageFeedbackAction({ opinion, url, message }: PageFeedback) {
  await analytics.track("page-feedback", { opinion, url, message });
  return {};
}
```

```tsx tab="press.config.tsx"
import { feedbackPlugin } from "@fumapress/feedback";
import { onPageFeedbackAction } from "./lib/feedback";

feedbackPlugin({ onPageFeedbackAction });
```

The returned `githubUrl`/`emailSent` tells the UI where the feedback went, the payload and response types are exported from `@fumapress/feedback/schema`.

Finally, initialize the `src/app.css` file and add the following:

```css title="src/app.css"
@import "tailwindcss";
@import "fumadocs-ui/css/neutral.css";
@import "fumadocs-ui/css/preset.css";
@import "fumapress/css/preset.css";
/* [!code ++] */
@import "@fumapress/feedback/css/preset.css";
```

### GitHub integration

<Callout type="warn" title="Prefer other platforms if possible">
  GitHub is not an analytics platform, it does not offer features like spam filtering.
</Callout>

1. Create your own GitHub App and obtain its app ID and private key.
2. Store them as **private** environment variables, **do not** share it.

   ```dotenv
   GITHUB_APP_ID=...
   GITHUB_PRIVATE_KEY=...
   ```

   <Callout>
     You can also use stronger methods like Key Vault, see [GitHub
     docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/managing-private-keys-for-github-apps)
     for managing private keys.
   </Callout>

3. Use the integration plugin:

   ```tsx title="press.config.tsx"
   import { defineConfig } from "fumapress";
   // [!code ++]
   import { githubFeedbackPlugin } from "@fumapress/feedback/github";

   export default defineConfig({
     // ...
   })
     // [!code highlight:12]
     .plugins(
       githubFeedbackPlugin({
         appId: process.env.GITHUB_APP_ID!,
         privateKey: process.env.GITHUB_PRIVATE_KEY!,
         // your repository info, e.g.
         storage: {
           owner: "fuma-nama",
           repo: "fumapress",
           category: "Feedback",
         },
       }),
     );
   ```

   Create a `Feedback` category in your GitHub Discussions, the bot will forward user feedbacks in the specified category.

### Email integration

Messages are sent with [Resend](https://resend.com) over HTTP. The API key stays on the server; the browser only calls your app’s feedback routes.

<Callout type="warn" title="Protect your inbox">
  Email is easy to abuse. Combine this with your own rate limiting, bot checks, or IP rules using
  the `beforeRequest` hook, and monitor Resend delivery and bounces in their dashboard.
</Callout>

1. Create a Resend account and [create an API key](https://resend.com/api-keys).
2. Store it as a **private** environment variable (never commit it or expose it to the client).

   ```dotenv
   RESEND_API_KEY=re_...
   ```

3. Configure a [verified sending domain](https://resend.com/docs/dashboard/domains/introduction) in Resend, and use a `from` address on that domain in production.
4. Use the email plugin:

   ```tsx title="press.config.tsx"
   import { defineConfig } from "fumapress";
   // [!code ++]
   import { emailFeedbackPlugin } from "@fumapress/feedback/email";

   export default defineConfig({
     // ...
   })
     // [!code highlight:9]
     .plugins(
       emailFeedbackPlugin({
         apiKey: process.env.RESEND_API_KEY!,
         from: "Docs <feedback@yourdomain.com>",
         to: "team@yourdomain.com",
         // optional: subject lines become `${subjectPrefix} /path`
         subjectPrefix: "[Docs feedback]",
       }),
     );
   ```

   `to` may be a single address or an array.

`feedbackPlugin()` and both integrations accept a `beforeRequest` hook that runs before each feedback request on the server. Return a `Response` to reject it (e.g. for rate limiting).

<Callout type="warn" title="Use only one feedback plugin">
  `feedbackPlugin()`, `githubFeedbackPlugin()` and `emailFeedbackPlugin()` all register
  `/api/feedback/page` and `/api/feedback/text`. Enabling more than one causes conflicts.
</Callout>
