---
title: Upgrade to Fumapress 2
description: Move a Fumapress 1.x site to version 2.
---

Fumapress 2 replaces `defineConfig()` with `createPress()`. The render mode of each page now matches its content source, so one site can have both prerendered and dynamic pages. Do the steps in order, then open the sections for the features your site uses.

## Upgrade Steps

### Update the Packages [step]

Update Fumapress and Fumadocs together. Also update any `@fumapress/*` plugins that you use.

```npm
npm i fumapress@latest
npm i fumadocs-core@latest fumadocs-mdx@latest
npm i fumadocs-ui@npm:@fumadocs/base-ui@latest
```

If you use the Radix UI build, replace the last line with `npm i fumadocs-ui@latest`.

### Rewrite the Config [step]

`content` and `i18n` go to `createPress()`. Plugins go to `.plugins()`, called once. Everything else goes to `.config()`.

The fields of `loaderOptions` also go to `createPress()`, without the `loaderOptions` wrapper. Rename `plugins` to `loaderPlugins`.

```tsx title="press.config.tsx"
// [!code --:2]
import { defineConfig } from "fumapress";
import { fumadocsMdx } from "fumapress/adapters/mdx";
// [!code ++]
import { createPress } from "fumapress";

// [!code --:7]
export default defineConfig({
  content: docs.toFumadocsSource(),
  loaderOptions: { plugins: [lucideIconsPlugin()] },
  site: { name: "My Docs" },
})
  .adapters(fumadocsMdx())
  .plugins(llmsPlugin());
// [!code ++:5]
export const app = createPress(docs.toFumadocsSource(), {
  loaderPlugins: [lucideIconsPlugin()],
}).plugins(llmsPlugin());

export default app.config({ site: { name: "My Docs" } });
```

Delete the `.adapters(fumadocsMdx())` call. MDX pages now render without it.

### Update the Schema Import [step]

```tsx title="press.config.tsx"
// [!code --]
import { metaSchema, pageSchema } from "fumapress/adapters/mdx/schema";
// [!code ++]
import { metaSchema, pageSchema } from "fumapress/schema";
```

### Run the Site [step]

```npm
npm run dev
```

If you didn't customize your site, you're done. To find the other changes, search your project for imports from `fumapress/` and for the options you set, then open the matching sections below.

## Site Options

Open the options your site sets.

<Accordions multiple>
<Accordion title="MDX components">

Move your components into a module, then pass it to `press()`. Relative links are resolved before your `a` component receives them, so `createRelativeLink()` is removed.

```tsx tab="src/components/mdx.tsx"
import defaultMdxComponents from "fumadocs-ui/mdx";
import { Tab, Tabs } from "fumadocs-ui/components/tabs";
import type { MDXComponents } from "mdx/types";

export default {
  ...defaultMdxComponents,
  Tab,
  Tabs,
} satisfies MDXComponents;
```

```ts tab="vite.config.ts"
export default defineConfig({
  // [!code --]
  plugins: [press(), fumadocsMdx(), tailwindcss()],
  // [!code ++]
  plugins: [press({ components: "./src/components/mdx.tsx" }), fumadocsMdx(), tailwindcss()],
});
```

</Accordion>
<Accordion title="Layouts">

The factories of `fumapress/layouts/*` are removed. If you call `createDocsLayoutPage()` without options, delete the call, since the Docs Layout is the default. Otherwise write the layout as JSX in `ui.renderPage`, and use `props.type` to choose it.

```tsx tab="1.x" title="press.config.tsx"
import { defineConfig } from "fumapress";
import { createNotebookLayoutPage } from "fumapress/layouts/notebook";

const Notebook = createNotebookLayoutPage<typeof config.$context>({
  treeRoot: "docs",
  render: () => ({ pageProps: { full: true } }),
});

const config = defineConfig({
  content,
  renderPage: (props) => <Notebook {...props} />,
});

export default config;
```

```tsx tab="2.0" title="press.config.tsx"
import { createPress, selectTreeRoot } from "fumapress";
import { DocsLayout } from "fumadocs-ui/layouts/notebook";
import { DocsBody, DocsPage, DocsTitle } from "fumadocs-ui/layouts/notebook/page";

export const app = createPress({ docs: docs.toFumadocsSource() });

export default app.config({
  ui: {
    renderPage(props) {
      const { renderDefault } = props;
      if (props.type !== "docs") return renderDefault();

      return (
        <DocsLayout {...props.baseOptions} tree={selectTreeRoot(props.tree, "docs")}>
          <DocsPage toc={props.pageData.toc} full>
            <DocsTitle>{props.pageData.title}</DocsTitle>
            <DocsBody>{props.body}</DocsBody>
            {Object.values(props.footer)}
          </DocsPage>
        </DocsLayout>
      );
    },
  },
});
```

Your JSX replaces options like `renderLayout`, `renderBody` and `pageProps`. Plugin buttons and forms are in `props.actions` and `props.footer`. See [Page Actions and Footers](/docs/layouts#page-actions-and-footers).

On custom pages, replace `createHomeLayout()` with [`HomeLayout`](/docs/custom-pages#layouts).

</Accordion>
<Accordion title="Navbar and links">

```tsx title="press.config.tsx"
export default app.config({
  // [!code --]
  defaultLayoutProps: { links: [{ url: "/blog", text: "Blog" }] },
  // [!code ++:3]
  ui: {
    baseOptions: { links: [{ url: "/blog", text: "Blog" }] },
  },
});
```

To read these options elsewhere, use `ctx.getBaseOptions({ lang })` in place of `ctx.defaultLayoutProps({ lang })`.

</Accordion>
<Accordion title="Root document and provider">

Props of the root provider move from `createRootLayout()` to `ui.providerProps`.

```tsx title="press.config.tsx"
// [!code --:4]
const Root = createRootLayout({
  providerProps: { theme: { defaultTheme: "dark" } },
});
defineConfig({ content, renderRoot: (props) => <Root {...props} /> });
// [!code ++:3]
createPress(content).config({
  ui: { providerProps: { theme: { defaultTheme: "dark" } } },
});
```

A custom `ui.renderRoot` also receives `head`, the styles of your site. Render it in `<head>`, or the page has no CSS.

</Accordion>
<Accordion title="Not found page">

Delete `renderNotFound`, and add the page as a file:

```tsx title="src/pages/404.tsx"
export default function NotFound() {
  return <main>This page doesn't exist.</main>;
}
```

</Accordion>
<Accordion title="Head tags">

`meta` returned JSX. `head` takes a list of tags, or a function that receives `page`.

```tsx title="press.config.tsx"
export default app.config({
  // [!code --:6]
  meta: {
    root: () => <link rel="icon" href="/favicon.ico" />,
    page(page) {
      return <meta name="robots" content="noindex" />;
    },
  },
  // [!code ++:4]
  head({ page }) {
    if (!page) return [{ tag: "link", attrs: { rel: "icon", href: "/favicon.ico" } }];
    return [{ tag: "meta", attrs: { name: "robots", content: "noindex" } }];
  },
});
```

For tags that don't depend on the page, pass a plain list. See [Head Tags](/docs/configuration#head-tags).

</Accordion>
<Accordion title="Languages and translations">

Pass `i18n` to `createPress()`, even when `translations` already had it, and move `translations` under `ui`.

`fumapress/i18n` is removed, so delete `.extend(fumapressTranslations())`. Plugin and UI strings are added for you.

```tsx title="press.config.tsx"
const i18n = defineI18n({ languages: ["en", "zh"], defaultLanguage: "en" });

// [!code --:4]
export default defineConfig({
  content,
  translations: i18n.translations().preset("zh", zhTW()),
});
// [!code ++:5]
export const app = createPress(content, { i18n });

export default app.config({
  ui: { translations: i18n.translations().preset("zh", zhTW()) },
});
```

</Accordion>
<Accordion title="Render mode">

Delete `mode`. Content from a static source, like Fumadocs MDX, is prerendered. Content from a dynamic source renders on demand, and one site can have both. Search and other generated files use the same render mode.

<Callout type="warn">
  If you used `mode: "dynamic"` with a static source, its pages no longer render on demand, so
  middleware doesn't run for them. See [Authentication](/docs/authentication) if you relied on that.
</Callout>

<Callout type="warn">
  `mode` no longer affects custom pages and API routes. Pages are prerendered and API routes render
  on demand unless `getConfig()` says otherwise.
</Callout>

</Accordion>
<Accordion title="Default plugins">

```tsx title="press.config.tsx"
createPress(content).config({
  // [!code --]
  preset: false,
  // [!code ++]
  preset: [],
});
```

Delete `preset: "recommended"`, since it is the default.

</Accordion>
<Accordion title="Search dialog">

A custom dialog moves to `ui.providerProps`, and receives the options of the search plugin as props. See [Custom Search Dialog](/docs/search#custom-search-dialog).

```tsx title="press.config.tsx"
createPress(content).config({
  ui: { providerProps: { search: { SearchDialog } } },
});
```

The exported search index is now at `/api/search.json`. On a dynamic source, search still runs at `/api/search`.

</Accordion>
<Accordion title="Custom pages and API routes">

Types and helpers are read through `app`, the result of `.plugins()`:

```tsx title="src/pages/showcase/[slug].tsx"
// [!code --:3]
import type { RouteConfig, RouteProps } from "fumapress";
import config from "../../../press.config";
const ctx = config.utils().getPressContext();
// [!code ++:3]
import { getPressContext, type WakuRouteConfig, type WakuRouteProps } from "fumapress";
import type { app } from "../../../press.config";
const ctx = getPressContext<typeof app>();

export function getConfig() {
  return {
    render: "static",
    // [!code --]
    takumiOptions: { title: "Showcase" },
    // [!code ++]
    ogImage: { title: "Showcase" },
    // [!code --]
  } satisfies RouteConfig;
  // [!code ++]
  } satisfies WakuRouteConfig;
}
```

`typeof config.$context` is now `typeof app`. Rename `AppContext<...>` to `PressContext<typeof app>`.

</Accordion>
<Accordion title="Server entry">

Add the `dispose` line, so that old plugins stop on hot reload. Pin `waku` to the version that Fumapress uses, `1.0.0-rc.1`.

```tsx title="src/waku.server.tsx"
const router = await createRouter(press);
// [!code ++]
import.meta.hot?.dispose(router.dispose);
```

</Accordion>
</Accordions>

## Plugins

Open the plugins your site uses.

<Accordions multiple>
<Accordion title="Blog">

The plugin moved to its own package, and `source` names a key of your content.

```npm
npm i @fumapress/blog
```

```css title="src/app.css"
@import "fumapress/css/preset.css";
/* [!code ++] */
@import "@fumapress/blog/css/preset.css";
```

```tsx title="press.config.tsx"
// [!code --:2]
import { blogPlugin } from "fumapress/plugins/blog";
import { blogPageSchema, blogMetaSchema } from "fumapress/adapters/mdx/schema";
// [!code ++:2]
import { blogPlugin } from "@fumapress/blog";
import { blogPageSchema, blogMetaSchema } from "@fumapress/blog/schema";

// [!code --]
blogPlugin();
// [!code ++]
blogPlugin({ source: "blog" });
```

If your `isBlog` picked posts from one source, move them to a separate source. Then update your calls to the blog helpers:

```tsx
// [!code --:3]
import { getBlogPosts, getBlogAuthors } from "fumapress/plugins/blog";
const posts = await getBlogPosts(ctx, lang);
const authors = await getBlogAuthors(ctx, posts[0].page);
// [!code ++:3]
import { getBlogPosts } from "@fumapress/blog";
const posts = await getBlogPosts(ctx, { lang });
const authors = posts[0]?.authors;
```

- Posts come with `authors`, `tags` and `image`. Use `tag.url` in place of `tagSlug()`.
- The `layouts` option becomes [`renderPage` cases](/docs/plugins/blog#custom-ui).
- The adapter keys `blog:get-tags`, `blog:get-authors` and `blog:get-image` become the options `getTags`, `getAuthors` and `getImage`.

</Accordion>

## Custom Plugins

Start with the type and the hooks that create routes. This plugin has a page, a generated file and a response header:

```tsx tab="1.x" title="acme/index.tsx"
import type { AppShape, PressPlugin } from "fumapress";

export function statusPlugin<C extends AppShape = AppShape>(): PressPlugin<C> {
  return {
    name: "acme:status",
    createPages({ createPage, createApiIsomorphic }) {
      createPage({
        path: "/status",
        render: "static",
        component: () => <p>OK</p>,
      });
      createApiIsomorphic({
        path: "/status.json",
        render: "static",
        handler: async () => Response.json({ ok: true }),
      });
    },
    createMiddlewares() {
      return [
        async (c, next) => {
          await next();
          c.header("x-powered-by", "acme");
        },
      ];
    },
  };
}
```

```tsx tab="2.0" title="acme/index.tsx"
import type { AppShape, Plugin } from "fumapress";

type StatusTypes = {
  views: { "status.page": {} };
};

export function statusPlugin<C extends AppShape = AppShape>(): Plugin<C, StatusTypes> {
  return {
    name: "acme:status",
    routes({ createApi, createView }) {
      createView({
        path: "/status",
        view: () => ({ type: "status.page", props: {}, node: <p>OK</p> }),
      });
      createApi({
        path: "/status.json",
        render: "static",
        GET: () => Response.json({ ok: true }),
      });
    },
    async middleware(_request, next) {
      const response = await next();
      const out = new Response(response.body, response);
      out.headers.set("x-powered-by", "acme");
      return out;
    },
  };
}
```

Then rename these APIs:

| 1.x                        | 2.0                         |
| -------------------------- | --------------------------- |
| `AppContext`               | `PressContext`              |
| `core:get-body`            | `getPageBody`               |
| `core:get-text`            | `getPageText`               |
| `core:render-toc`          | `getPageToc`                |
| `core:get-structured-data` | `getPageStructuredData`     |
| `core:get-creation-date`   | `getPageCreatedAt`          |
| `core:get-modified-date`   | `getPageLastModified`       |
| `unstable_onServerEntry`   | `waku.unstable_serverEntry` |

`enforce` is removed, since plugins run in list order. `preinit` becomes [`provides`](/docs/plugins/authoring#capabilities), and `this.mode` becomes [`this.getContentRender()`](/docs/plugins/authoring/routes#content-render-mode).

These need more than a rename:

<Accordions multiple>
<Accordion title="Waku pages and Hono">

A plugin that needs Waku's own APIs moves them under `waku`, and uses the `WakuPlugin` type. See [Waku APIs](/docs/plugins/authoring/server#waku-apis).

```tsx title="acme/index.tsx"
// [!code --]
export function acmePlugin<C extends AppShape = AppShape>(): PressPlugin<C> {
// [!code ++]
export function acmePlugin<C extends WakuAppShape = WakuAppShape>(): WakuPlugin<C> {
  return {
    name: "acme",
    // [!code --:2]
    createPages({ createPage }) { /* ... */ },
    createMiddlewares() { /* ... */ },
    // [!code ++:4]
    waku: {
      createPages({ createPage }) { /* ... */ },
      honoMiddleware() { /* ... */ },
    },
  };
}
```

</Accordion>
<Accordion title="Rendering pages">

The `renderPage` hook becomes `getPageView`. It returns `{ props, node }` for the pages of a source your plugin owns. See [Rendering Content Pages](/docs/plugins/authoring/ui#rendering-content-pages).

```tsx title="acme/index.tsx"
// [!code --:4]
renderPage({ page, fallback }) {
  if (page.type !== "reviews") return;
  return <article>{fallback}</article>;
},
// [!code ++:4]
getPageView(page, body) {
  if (page.type !== "reviews") return;
  return { props: {}, node: <article>{body?.node}</article> };
},
```

</Accordion>
<Accordion title="Routes of other plugins">

`configureRoutes` becomes `deriveRoutes`, which receives the routes of each language. Head tags from `route.meta` move to the `head` hook, which receives `route`.

```tsx title="acme/index.tsx"
// [!code --:3]
configureRoutes({ getRoutes }) {
  for (const route of getRoutes()) route.meta.push(() => <meta name="acme" content="1" />);
},
// [!code ++:3]
head({ route }) {
  if (route) return [{ tag: "meta", attrs: { name: "acme", content: "1" } }];
},
```

</Accordion>
<Accordion title="UI from this.data">

`this.data` and its transformers and interceptors are removed. Add UI with [`slots()`](/docs/plugins/authoring/ui#slots), and change page data with [`transformPage()`](/docs/plugins/authoring/ui#page-data). Plugin translations move to the `translations` field.

```tsx title="acme/index.tsx"
{
  name: "acme",
  // [!code --:3]
  init() {
    this.translationsConfig?.extend(acmeTranslations());
  },
  // [!code ++]
  translations: acmeTranslations(),
}
```

</Accordion>
