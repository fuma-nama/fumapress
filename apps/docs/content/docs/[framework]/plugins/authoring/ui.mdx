## Slots

This plugin adds a share button below the title of every content page:

```tsx tab="acme/index.tsx"
import { ShareButton } from "./share-button";

type Types = { slots: "acme:share" };

export function sharePlugin<C extends AppShape = AppShape>(): Plugin<C, Types> {
  return {
    name: "acme:share",
    slots({ page }) {
      if (!page) return; // [!code highlight]
      return [
        {
          name: "acme:share", // [!code highlight]
          region: "actions", // [!code highlight]
          component: ShareButton,
          props: { url: this.absoluteUrl(page.url) },
        },
      ];
    },
  };
}
```

```tsx tab="acme/share-button.tsx"
"use client";

export function ShareButton({ url }: { url: string }) {
  return (
    <button type="button" onClick={() => navigator.clipboard.writeText(url)}>
      Share
    </button>
  );
}
```

`slots` runs with `page` for the items of a content page, and without `page` for the items of every page. Each item has a name, unique on the site, written as `<plugin>:<item>`. List the names in the `slots` of your plugin types. Names starting with `core:` belong to Fumapress.

The built-in UI places an item in its region. A custom layout places it by name, with `props.slots["acme:share"]`.

To translate the label, add your strings with the `translations` field. See the [Fumadocs Translations API](https://fumadocs.dev/docs/ui/translations).

### Regions

The regions marked for content pages take items from the call with `page`, the others from the call without. An item in a region of the other call is an error:

`ui.renderPage` receives the items of every region but the wrappers and `banner` as `props.slots`. A layout without a region doesn't render its items, like the Home Layout of plugin pages, which has none of them.

### Wrapper Slots

A wrapper receives what it wraps as `children`:

```tsx tab="acme/index.tsx"
slots({ page }) {
  if (page) return [{ name: "acme:prose", region: "body-wrapper", component: Prose }];
  return [{ name: "acme:theme", region: "layout-wrapper", component: ThemeProvider, order: -10 }];
},
```

```tsx tab="The page"
<ThemeProvider>
  {/* the layout */}
  <Prose>{/* the content */}</Prose>
</ThemeProvider>
```

Two wrappers in one region are nested by `order`, with the lowest on the outside. Context providers use a negative order.

## Layout Props

`layoutProps` adds to the [layout props](../../configuration.mdx#navbar-and-links) of every layout, like links, `sidebar` and `tabs`. It runs for each page, with `page` on content pages. Its links come after the links of the site, and for other props the values of the site take priority.

```tsx title="acme/index.tsx"
layoutProps({ lang }) {
  return {
    links: [{ url: this.localizePath(lang, "/showcase"), text: "Showcase" }],
  };
},
```

`providerProps` does the same for the [root provider](https://fumadocs.dev/docs/ui/layouts/root-provider).

## Head Tags

`head` runs once for the whole site without `page` or `route`, and once for each page. A tag from the `head` option of the site replaces a plugin tag with the same key, like a `meta` tag of the same name.

```tsx title="acme/index.tsx"
head({ page, route }) {
  if (page) return [{ tag: "meta", attrs: { name: "author", content: "acme" } }];
  if (route) return;
  return [{ tag: "meta", attrs: { name: "generator", content: "acme" } }];
},
```

## Rendering Content Pages

To show the pages of one source differently, write `getPageView`. This plugin gives each page of the `reviews` source a star rating and its own UI:

```tsx tab="acme/reviews.tsx"
type Types = {
  pages: { reviews: { stars: number } }; // [!code highlight]
};

export function reviewsPlugin<C extends AppShape = AppShape>(): Plugin<C, Types> {
  return {
    name: "acme:reviews",
    getPageView(page, body) {
      if (page.type !== "reviews") return; // [!code highlight]
      const stars = Number(Reflect.get(page.data, "stars") ?? 0);

      return {
        props: { stars }, // [!code highlight]
        node: (
          <article>
            <p>{"★".repeat(stars)}</p>
            {body?.node} {/* [!code highlight] */}
          </article>
        ),
      };
    },
  };
}
```

```tsx tab="press.config.tsx"
import { HomeLayout } from "fumadocs-ui/layouts/home";

export const app = createPress({
  docs: docsSource,
  reviews: reviewsSource,
}).plugins(reviewsPlugin());

export default app.config({
  ui: {
    renderPage(props) {
      const { renderDefault } = props;
      if (props.type === "reviews") {
        // the Home Layout takes these props, the others are for docs layouts
        const { nav, links, githubUrl, i18n, themeSwitch, searchToggle } = props.layoutProps;
        const home = { nav, links, githubUrl, i18n, themeSwitch, searchToggle };
        return (
          <HomeLayout {...home}>
            <h1>
              {props.pageData.title}, {props.stars} stars {/* [!code highlight] */}
            </h1>
            {props.children} {/* [!code highlight] */}
          </HomeLayout>
        );
      }
      return renderDefault();
    },
  },
});
```

- `pages` maps a source key to the props that the plugin adds.
- `page.type` is the source of the page. Return `undefined` for pages of other sources.
- `body.node` is the content of the page.
- `props` are passed to `ui.renderPage` as they are, and `node` becomes `props.children`.

Without a `ui.renderPage`, `node` shows in the Home Layout.

### Page Rendering Order

Each step receives the result of the one above. Write the hook of the step you want to change.

<Flow>
  <FlowStep title="getPageBody(page)" result="{ node }">
    The content. The content source provides it, so only write this hook for a custom source.
  </FlowStep>
  <FlowStep title="body-wrapper slots" result="props.body">
    Wrap the content of every source.
  </FlowStep>
  <FlowStep title="getPageView(page, body)" result="props.children">
    Adds props and UI to the pages of one source.
  </FlowStep>
  <FlowStep title="ui.renderPage(props)" result="the page">
    Set by the site. It renders everything above in a layout.
  </FlowStep>
</Flow>

### Page Data

`transformPage` changes the page data of every page: content pages, plugin pages and custom pages. A layout reads it from `props.pageData`, like the title or the width, and `<head>` gets its title and description. Return only the fields you change. Two plugins changing the same field is an error.

```tsx title="acme/index.tsx"
transformPage(data) {
  return { full: data.url.startsWith("/reference/") };
},
```

It receives `page` on content pages, and `route` with `path` on other pages. Read the page data of any page with `this.getPageData()`.

## React Content

The React content of a plugin renders on the server, in an island. Only client components (`"use client"`) and components of the [MDX components](../../content.mdx#components) module hydrate. Other components can't use state or effects.

<Callout type="warn">
  Props of hydrating components must be serializable: strings, numbers, dates, maps, JSX elements
  and client components work. A client component with a function prop throws an error that names the
  prop.
</Callout>
