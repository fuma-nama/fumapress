Search works without setup, with FlexSearch. The build exports an index of your pages, and the browser downloads and searches it. With a dynamic source, like [Notion](./content-sources/notion.mdx), search runs on your server instead, since the pages change after the build.

## Search Engines

FlexSearch is the default, and `search` of `recommendedPreset()` takes its options, like in [Customization](#customization). To use another engine, set `search: false` and add the plugin of the engine. Without one, the site has no search:

<show when={props.framework === "waku"}>

```tsx tab="Orama" title="press.config.tsx"
import { createPress, recommendedPreset } from "fumapress";
import { oramaSearchPlugin } from "fumapress/plugins/orama-search";

export const app = createPress(content).plugins(oramaSearchPlugin());

export default app.config({
  preset: recommendedPreset({ search: false }),
});
```

```tsx tab="None" title="press.config.tsx"
import { createPress, recommendedPreset } from "fumapress";

createPress(content).config({
  preset: recommendedPreset({ search: false }),
```

## Customization

These options work with both FlexSearch and Orama.

### Server-Side Search

On a large site, the index is a big download for every reader. To keep the index on the server, set the `render` option of the search plugin. The site then [needs a server](./deployment.mdx#what-needs-a-server).

```tsx tab="FlexSearch" title="press.config.tsx"
createPress(content).config({
  preset: recommendedPreset({ search: { render: "dynamic" } }),
});
```

```tsx tab="Orama" title="press.config.tsx"
oramaSearchPlugin({ render: "dynamic" });
```

### Search Index

The index contains the headings and text of each page, from your content source. Pages without headings and text are searched by title.

Both plugins take `buildIndex` to change the fields. The result must include `structuredData`, the headings and text. This example adds a `tag` to each page, so that a [dialog](#custom-search-dialog) can filter by it:

```tsx title="press.config.tsx"
recommendedPreset({
  search: {
    async buildIndex(page) {
      const data = await this.getPageStructuredData(page);

      return {
        id: page.url,
        title: page.data.title ?? page.path,
        description: page.data.description,
        url: page.url,
        structuredData: data ?? { headings: [], contents: [] },
        tag: page.path.split("/")[0], // [!code highlight]
      };
    },
  },
});
```

Search results show the same breadcrumb as the page. To change it, return `breadcrumbs` from `buildIndex`.

### Custom Search Dialog

Compose a dialog from the parts of Fumadocs UI and a [search hook](https://fumadocs.dev/docs/headless/search), then pass it through `ui.providerProps`. The dialog receives the options of the search plugin as props.

```tsx tab="src/search.tsx"
"use client";
import {
  useFlexsearchStatic,
  type FlexsearchStaticOptions,
} from "fumadocs-core/search/client/flexsearch-static";
import {
  SearchDialog as Dialog,
  SearchDialogContent,
  SearchDialogHeader,
  SearchDialogInput,
  SearchDialogList,
  SearchDialogOverlay,
  type SharedProps,
} from "fumadocs-ui/components/dialog/search";

type Props = SharedProps & FlexsearchStaticOptions;

export function SearchDialog({ from, locale, ...props }: Props) {
  return (
    <Dialog {...props} {...useFlexsearchStatic({ from, locale, tag: "guides" })}>
      <SearchDialogOverlay />
      <SearchDialogContent>
        <SearchDialogHeader>
          <SearchDialogInput />
        </SearchDialogHeader>
        <SearchDialogList />
      </SearchDialogContent>
    </Dialog>
  );
}
```

```tsx tab="press.config.tsx"
import { SearchDialog } from "./src/search";

createPress(content).config({
  ui: { providerProps: { search: { SearchDialog } } },
});
```

When search runs on the server, the props are `api` and `locale`, and the hook is `useFetchSearch` from `fumadocs-core/search/client/fetch`.
