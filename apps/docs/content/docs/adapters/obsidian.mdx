title: Obsidian
description: Render an Obsidian vault directly with Fumapress.
---

Vault notes are compiled in memory without generating intermediate MDX files, and the renderer stays on the server. Supported Obsidian syntax includes wikilinks and embeds, callouts, block IDs and comments.

## Installation

```npm
npm i fumadocs-obsidian
```

Import its Tailwind source after the Fumadocs UI styles:

```css title="src/app.css"
@import "fumadocs-obsidian/css/preset.css";
```

## Configuration

For a runnable project, see [`examples/obsidian`](https://github.com/fuma-nama/fumapress/tree/main/examples/obsidian).

Create the vault source, pass it to `createPress`, and register `obsidianPlugin()`:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { obsidian } from "fumadocs-obsidian";
import obsidianPlugin from "fumadocs-obsidian/press";

const vault = obsidian({
  dir: "public/vault",
  url: (file) => `/vault/${file}`,
});

export default createPress(vault.dynamicSource())
  .plugins(obsidianPlugin({ vault }))
  .config({
    site: { name: "My Vault" },
  });
```

`page.data.load()` compiles a note at most once per vault snapshot. Media files are mapped to URLs and are not read into memory. Ambiguous wikilinks resolve like Obsidian: notes take precedence over attachments, then the shortest path wins.

### Development Watching

`localContentPlugin()` watches the vault in the dev server and reloads the page on changes. `watchWithVite()` connects the vault to it:

```ts tab="vite.config.ts"
import { defineConfig } from "vite";
import { localContentPlugin } from "fumadocs-obsidian/dev/vite";
import tailwindcss from "@tailwindcss/vite";
import press from "fumapress/vite";

export default defineConfig({
  plugins: [press(), localContentPlugin(), tailwindcss()],
});
```

```tsx tab="press.config.tsx"
import { watchWithVite } from "fumadocs-obsidian/dev/vite";

// [!code ++]
if (import.meta.env.DEV) watchWithVite(vault);
```

Because wikilinks and aliases can create cross-file dependencies, a vault change invalidates the source snapshot. Only changed files are read from disk again.

## Rendering

The plugin supplies Fumadocs UI MDX components, Obsidian callout components and relative-link resolution. Pass Fumadocs UI defaults and add or replace components through `components`:

```tsx title="press.config.tsx"
import defaultMdxComponents from "fumadocs-ui/mdx";

obsidianPlugin({
  vault,
  components: {
    ...defaultMdxComponents,
    img: (props) => <img {...props} className="rounded-xl" />,
  },
});
```

The same compiled representation supplies the page body, table of contents, structured search data and plain text for LLM exports.

## Vault Schema

The source accepts Standard Schema validators for frontmatter and `meta.json` files. It also supports additional remark and rehype plugins for syntax such as Mermaid and math. See the [Fumadocs Obsidian integration](https://fumadocs.dev/docs/integrations/obsidian) for the complete source configuration.
