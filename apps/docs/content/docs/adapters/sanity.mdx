## Installation

```npm
npm i @fumadocs/sanity @sanity/client
```

## Document Schema

Point the integration at a document type in your Sanity Studio, with the fields:

| Field         | Type                          |
| ------------- | ----------------------------- |
| `title`       | string (required)             |
| `slug`        | slug (required)               |
| `description` | string                        |
| `body`        | block content (Portable Text) |

For a complete Studio, see [`examples/example-sanity-studio`](https://github.com/fuma-nama/fumapress/tree/main/examples/example-sanity-studio), which also defines custom block types like callouts, cards, tabs, steps and accordions.

## Configuration

For a runnable project, see [`examples/example-sanity`](https://github.com/fuma-nama/fumapress/tree/main/examples/example-sanity).

Create the integration once, use it as the content source, and pass `sanityPlugin()` to render its pages:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { createSanitySource } from "@fumadocs/sanity";
import sanityPlugin from "@fumadocs/sanity/press";
import { createClient } from "@sanity/client";

const source = createSanitySource({
  client: createClient({
    projectId: process.env.SANITY_STUDIO_PROJECT_ID,
    dataset: process.env.SANITY_STUDIO_DATASET,
    apiVersion: "2024-12-04",
  }),
  docType: "docs",
});

export default createPress(source, {
  loaderOptions: { alwaysRevalidate: true },
})
  .plugins(sanityPlugin())
  .config({ mode: "dynamic" });
```

`alwaysRevalidate` is the simplest way to reflect Sanity edits immediately. For a higher-traffic site, leave it disabled and call `revalidateLoader()` from a trusted webhook or revalidation route instead.

### Paths

Page URLs are generated from the `slug` field, which may contain `/` for nested routes. Use `baseDir` to place the pages under a directory, or `generatePath` for complete control:

```tsx
createSanitySource({
  // ...
  baseDir: "docs",
  generatePath(doc) {
    return `${doc.slug?.current ?? doc._id}.mdx`;
  },
});
```

## Rendering

`sanityPlugin()` renders the Portable Text body and extracts the table of contents, plain text for search and dates from the document. Pass Portable Text `components` to support your own block types:

```tsx title="press.config.tsx"
import { Callout } from "fumadocs-ui/components/callout";

sanityPlugin({
  components: {
    types: {
      callout: ({ value }) => <Callout title={value.title}>{/* ... */}</Callout>,
    },
  },
});
```

The example project includes ready-made mappings for callouts, cards, files, tabs, steps and accordions.

See the [Fumadocs Sanity integration](https://fumadocs.dev/docs/integrations/sanity) for the full source configuration.
