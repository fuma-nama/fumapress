## Overview

Every page goes through `ui.renderPage`. Without it, the built-in UI renders the [Docs Layout](/docs/layouts/docs) for content pages and the [Home Layout](/docs/layouts/home) for plugin views.

## Render Page

`ui.renderPage` receives props typed by the page's source or plugin view. `props.type` is a source key (`"docs"`) or a view type (`"blog"`, `"blog.index"`). Content pages get `page`, `slugs`, `pageData`, `body`, `actions` and `footer`. Views get their own typed props plus `children`. Every page gets `lang`, `tree`, `baseOptions` and `renderDefault()`.

Take `renderDefault` out of `props` before the switch. Once every type has a case, `props` is `never` in `default`.

```tsx tab="src/ui/layout.tsx"
import { selectTreeRoot, type RenderPageProps } from "fumapress";
import { DocsLayout } from "fumadocs-ui/layouts/notebook";
import {
  DocsBody,
  DocsDescription,
  DocsPage,
  DocsTitle,
  MarkdownCopyButton,
  ViewOptionsPopover,
} from "fumadocs-ui/layouts/notebook/page";
import { HomeLayout } from "fumadocs-ui/layouts/home";
import type { app } from "../../press.config";

function Docs({ tree, baseOptions, pageData, body, actions }: RenderPageProps<typeof app, "docs">) {
  return (
    <DocsLayout {...baseOptions} tree={selectTreeRoot(tree, "docs")}>
      <DocsPage toc={pageData.toc} full={pageData.full}>
        <DocsTitle>{pageData.title}</DocsTitle>
        <DocsDescription>{pageData.description}</DocsDescription>
        <div className="flex gap-2">
          {pageData.markdownUrl && <MarkdownCopyButton markdownUrl={pageData.markdownUrl} />}
          <ViewOptionsPopover markdownUrl={pageData.markdownUrl} githubUrl={pageData.githubUrl} />
          {Object.values(actions)}
        </div>
        <DocsBody>{body}</DocsBody>
      </DocsPage>
    </DocsLayout>
  );
}

export function renderPage(props: RenderPageProps<typeof app>) {
  const { renderDefault } = props;
  switch (props.type) {
    case "docs":
      return <Docs {...props} />;
    case "blog":
    case "blog.index":
    case "blog.tags":
    case "blog.tag":
      return (
        <HomeLayout {...props.baseOptions}>
          <main className="mx-auto w-full max-w-[1400px] px-4 py-6">{props.children}</main>
        </HomeLayout>
      );
    default:
      return renderDefault();
  }
}
```

```tsx tab="press.config.tsx"
import { createPress } from "fumapress";
import { defineDocs } from "fumadocs-mdx/macro";
import { blogPlugin } from "@fumapress/blog";
import { renderPage } from "./src/ui/layout";

const docs = defineDocs({ dir: "content/docs", docs: { async: true } });
const blog = defineDocs({ dir: "content/blog" });

export const app = createPress({
  docs: docs.toFumadocsSource({ baseDir: "docs" }),
  blog: blog.toFumadocsSource({ baseDir: "blog" }),
}).plugins(blogPlugin({ source: "blog" }));

export default app.config({
  site: { name: "Acme" },
  ui: { renderPage },
});
```

Type a component with `RenderPageProps<typeof app, "docs">` to narrow the props to one source or view.

## Base Options

`ui.baseOptions` is shared by every layout and by your own pages through the site context's `getBaseOptions({ lang })`. Set it as an object or as a function of `lang`. Plugins add their own links under it. The site's own values win.

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
// ...

export default app.config({
  // ...
  ui: {
    baseOptions: {
      nav: { title: "Acme" },
      links: [{ url: "/blog", text: "Blog", active: "nested-url" }],
    },
  },
});
```

## Switching Layouts

Switch on `props.type` to render each source with a different layout.

```tsx title="src/ui/layout.tsx"
export function renderPage(props: RenderPageProps<typeof app>) {
  const { renderDefault } = props;
  switch (props.type) {
    case "guides":
      return <Guide {...props} />;
    case "docs":
      return <Docs {...props} />;
    default:
      return renderDefault();
  }
}
```

A condition on `props.page.path` works too, for example rendering pages under `reference/` with a different layout. With several sources, see [Content Collections](/docs/collections).

## Page Actions and Footers

`actions` and `footer` are slot items added by your plugins, keyed by name. The AI plugin adds `actions.ai` and the feedback plugin adds `footer.feedback`. Place them in your page JSX, or spread all of them with `Object.values(actions)`.

```tsx title="src/ui/layout.tsx"
function Docs({
  tree,
  baseOptions,
  pageData,
  body,
  actions,
  footer,
}: RenderPageProps<typeof app, "docs">) {
  return (
    <DocsLayout {...baseOptions} tree={selectTreeRoot(tree, "docs")}>
      <DocsPage toc={pageData.toc}>
        <div className="flex justify-end">{actions.ai}</div>
        <DocsTitle>{pageData.title}</DocsTitle>
        <DocsBody>{body}</DocsBody>
        {footer.feedback}
      </DocsPage>
    </DocsLayout>
  );
}
```

See [AI](/docs/plugins/ai) and [Feedback](/docs/plugins/feedback) for the plugins that provide these slots.
