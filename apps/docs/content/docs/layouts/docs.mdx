## Overview

Use the docs layout for documentation pages with sidebar navigation, page title, description, table of contents, view options, and last updated time.

Fumapress uses this layout by default, so you only need to configure it when you want to customize the renderer.

## Config

Define the layout and pass it through `renderPage`.

```tsx title="press.config.tsx"
import { defineConfig } from "fumapress";
import { createDocsLayoutPage } from "fumapress/layouts/docs";

const DocsLayout = createDocsLayoutPage<typeof config.$context>();

const config = defineConfig({
  // [!code ++]
  renderPage: (props) => <DocsLayout {...props} />,
});

export default config;
```

Customize what the layout renders with the `render` option:

```tsx title="press.config.tsx"
import { defineConfig } from "fumapress";
import { createDocsLayoutPage } from "fumapress/layouts/docs";

const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  async render(page) {
    return {
      pageProps: {
        tableOfContent: {
          style: "clerk",
        },
      },
    };
  },
});

const config = defineConfig({
  // ...
  renderPage: (props) => <DocsLayout {...props} />,
});

export default config;
```

The `render` function can return page props, layout props, markdown URL, last modified date, or a custom body.

## Options

### `treeRoot`

The sidebar shows the whole page tree, which spans every collection in a multi-source setup. Pass the folder path to use as the root instead, such as the `baseDir` of a [content collection](/docs/collections):

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  // [!code ++]
  treeRoot: "docs",
});

const config = defineConfig({
  content: {
    docs: docs.toFumadocsSource({ baseDir: "docs" }),
    blog: blog.toFumadocsSource({ baseDir: "blog" }),
  },
  renderPage: (props) => <DocsLayout {...props} />,
});
```

Nested paths like `docs/guides` work too, and an unknown path throws with the list of available folders.

### Interceptors

`render` returns props. For full control over the rendered components, intercept them instead:

- `renderLayout`: wraps `<DocsLayout />`.
- `renderPage`: wraps `<DocsPage />`.
- `renderBody`: wraps the body element.
- `renderPageActions`: wraps the page actions, the Markdown copy button and view options menu shown under the page description.

Each receives the resolved props and a `next` function rendering the original component:

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  renderPage({ props, next }) {
    return next({
      ...props,
      children: (
        <>
          {props.children}
          <Comments />
        </>
      ),
    });
  },
});
```

Return your own node instead of calling `next` to replace the component. For example, to hide the page actions:

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  // [!code ++]
  renderPageActions: () => null,
});
```

Or to keep the Markdown copy button without the view options menu:

```tsx title="press.config.tsx"
import { MarkdownCopyButton } from "fumadocs-ui/layouts/docs/page";

const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  renderPageActions({ props }) {
    if (!props.markdownUrl) return null;

    return (
      <div className="flex flex-row gap-2 items-center border-b pt-2 pb-6">
        <MarkdownCopyButton markdownUrl={props.markdownUrl} />
      </div>
    );
  },
});
```

### `inherit`

By default, layouts merge `defaultLayoutProps` into their props, set `inherit: { layoutProps: false }` to opt out.
