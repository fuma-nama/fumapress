![Docs Layout](/layouts/docs.webp)

See [Fumadocs Docs Layout](https://fumadocs.dev/docs/ui/layouts/docs) and [Docs Page](https://fumadocs.dev/docs/ui/layouts/page) for the available props.

Fumapress uses it by default. To customize it, create the layout and pass it to `renderPage`:

```tsx title="press.config.tsx"
import { defineConfig } from "fumapress";
import { createDocsLayoutPage } from "fumapress/layouts/docs";

const DocsLayout = createDocsLayoutPage<typeof config.$context>();

const config = defineConfig({
  // ...
  renderPage: (props) => <DocsLayout {...props} />,
});

export default config;
```

## Options

### `render`

Return `pageProps`, `layoutProps`, `markdownUrl`, `lastModified`, or a custom `body` for each page:

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  async render(page) {
    return {
      pageProps: {
        tableOfContent: { style: "clerk" },
      },
    };
  },
});
```

### `treeRoot`

Use a folder as the sidebar root instead of the whole page tree, such as the `baseDir` of a [content collection](/docs/collections). Nested paths like `docs/guides` work too.

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  treeRoot: "docs",
});
```

### Interceptors

`renderLayout`, `renderPage`, `renderBody`, and `renderPageActions` wrap `<DocsLayout />`, `<DocsPage />`, the body, and the page actions. Each receives the resolved props and a `next` function rendering the original component, return your own node to replace it:

```tsx title="press.config.tsx"
const DocsLayout = createDocsLayoutPage<typeof config.$context>({
  renderPage({ props, next }) {
    return next({
      ...props,
      children: (
        <>
          {props.children}
          <Comments />
        </>
      ),
    });
  },
  // hide the page actions
  renderPageActions: () => null,
});
```

### `inherit`

Set `inherit: { layoutProps: false }` to stop merging `defaultLayoutProps`.
