```js title="astro.config.mjs"
export default defineConfig({
  integrations: [
    press({ components: "./src/components/mdx.tsx" }), // [!code highlight]
  ],
});
```

### Use the Components [step]

<include cwd>content/shared/content.mdx#usage</include>

### Rules for the Module

The content of a page is a React island of its own, so:

- **Props** must be serializable, since components hydrate by name. `<Chart data={[1, 2]} />` runs in the browser, and `<Chart onClick={() => {}} />` renders on the server only.
- **Providers** from your layout don't reach the content. Add a `wrapper` to the MDX components instead.
- **Imports** also load in the browser, so keep server-only code out.

<Callout type="warn" title="No cycles">
  Don't import `press.config.tsx` or `@fumapress/astro/runtime` from the module. The cycle with your
  content slows the build down.
</Callout>

### One Module per Collection

```js title="astro.config.mjs"
press({
  components: "./src/components/mdx.tsx",
  collections: {
    docs: { dir: "content/docs" },
    blog: { dir: "content/blog", components: "./src/components/blog-mdx.tsx" }, // [!code ++]
  },
});
```

### Custom Links

<include cwd>content/shared/content.mdx#custom-links</include>

<Callout type="warn">
  Astro renders your `a` on its own, like in Astro MDX: no hydration, and no React context from the
  page. It can't use state, effects or hooks like `usePathname`. The same goes for an MDX component
  inside a link.
</Callout>

## Images and Files

<include cwd>content/shared/content.mdx#files</include>

On custom pages, use [Astro Images](https://docs.astro.build/en/guides/images/).

```astro title="src/pages/index.astro"
---
import { Image } from "astro:assets";
import screenshot from "../assets/screenshot.png";
---

<Image src={screenshot} alt="A preview of the editor" />
```
