## Content Collections [#collections]

Docs are MDX files of Astro content collections. `pageLoader()` and `metaLoader()` of `@fumadocs/astro` load the content directory, and `toFumadocsSource()` turns them into a content source. See [Getting Started](/docs/astro#manual-installation) for the files.

Pages and `meta.json` files follow the [Fumadocs conventions](https://fumadocs.dev/docs/page-conventions), and the loaders validate frontmatter with `pageSchema` of `fumadocs-core/source/schema`. Add fields with a `schema` of your own:

```ts title="src/content.config.ts"
import { defineCollection } from "astro:content";
import { z } from "astro/zod";
import { pageSchema } from "fumadocs-core/source/schema";
import { metaLoader, pageLoader } from "@fumadocs/astro/loaders";

export const collections = {
  docs: defineCollection({
    loader: pageLoader(),
    // [!code ++]
    schema: pageSchema.extend({ draft: z.boolean().optional() }),
  }),
  meta: defineCollection({ loader: metaLoader() }),
};
```

### Multiple Collections

`content/docs` is the default collection of `press()`. To add another directory, list every collection in `collections`, and give each source a `baseDir` in its third argument:

```js tab="astro.config.mjs"
import { defineConfig } from "astro/config";
import press from "@fumapress/astro";

export default defineConfig({
  integrations: [
    press({
      collections: {
        docs: { dir: "content/docs" },
        // [!code ++]
        blog: { dir: "content/blog" },
      },
    }),
  ],
});
```

```ts tab="src/content.config.ts"
export const collections = {
  docs: defineCollection({ loader: pageLoader() }),
  meta: defineCollection({ loader: metaLoader() }),
  // [!code ++:2]
  blog: defineCollection({ loader: pageLoader("blog") }),
  blogMeta: defineCollection({ loader: metaLoader("blog") }),
};
```

```tsx tab="press.config.tsx"
import { getCollection } from "astro:content";
import { toFumadocsSource } from "@fumadocs/astro/source";
import { createPress } from "@fumapress/astro/config";

export default createPress({
  docs: toFumadocsSource(await getCollection("docs"), await getCollection("meta"), {
    baseDir: "docs",
  }),
  // [!code ++]
  blog: toFumadocsSource(await getCollection("blog"), await getCollection("blogMeta"), {
    baseDir: "blog",
  }),
}).config({});
```

The keys of `content` become the `type` of pages. See [Content Collections](/docs/collections). Collections take the options of `press()` as defaults, and can set their own, like `components`.

### Last Modified

`lastModified` adds the date of the last commit to pages, from the git history of the content directory. Layouts show it, and the sitemap and RSS feed use it:

```js title="astro.config.mjs"
press({
  // [!code ++]
  lastModified: true,
});
```

It reads the history at build time: uncommitted pages have no date, and a shallow clone (common in CI) gives every page the date of the latest commit.

## MDX Components

Pages render with the MDX components of Fumadocs UI. To add your own, create a module whose default export is the MDX components:

```tsx tab="src/components/mdx.tsx"
import defaultMdxComponents from "fumadocs-ui/mdx";
import { Tab, Tabs } from "fumadocs-ui/components/tabs";
import type { MDXComponents } from "mdx/types";

export default {
  ...defaultMdxComponents,
  Tab,
  Tabs,
} satisfies MDXComponents;
```

```js tab="astro.config.mjs"
press({
  // [!code ++]
  components: "./src/components/mdx.tsx",
});
```

The module also applies on your own pages through `getProviderData`. See [Rendering Content](/docs/astro/routing#rendering-content).

The content of a page is one React island. See the [rendering rules](https://fumadocs.dev/docs/manual-installation/astro#rendering) of Fumadocs. The module loads on every page and in the browser: keep server-only code out of it, and don't import `press.config.tsx` or `@fumapress/astro/runtime` from it. The cycle with your content slows the build down.

## React Content

React content of plugins and the press config, like the pages of [OpenAPI](/docs/plugins/openapi), slot items and JSX in `ui.baseOptions`, renders on the server and hydrates as an island. Parts of it hydrate:

- Client components, from modules starting with `"use client"`.
- The components of your MDX components module.

Other components render once on the server. They cannot use state or effects. Props of hydrating components must be serializable: strings, numbers, dates, maps, JSX elements and client components work. A client component with a function prop throws an error naming the component, and an MDX component with one renders on the server.

Navigating between pages keeps the island and its state, like the open folders of the sidebar.

The page body is an island of its own. Providers in `ui.renderPage` and in `body.wrapper` don't reach it. Give the [MDX components](#mdx-components) their own `wrapper` instead.

Feedback server actions work through routes on Astro. Client actions, like calling an external API from the browser, work as they do on Waku. See [Deployment](/docs/astro/deployment#adapters) for plugins that need a server.

## Other Sources

Other content sources join the `createPress` call like collections, and their plugins render them, like the pages of [OpenAPI](/docs/plugins/openapi).

Sources whose pages render Markdown at runtime, like [Local Markdown](https://fumadocs.dev/docs/integrations/content/local-md), need no plugin. They render with your MDX components, and relative links are resolved. Notion and Sanity render with the default exports of `@fumadocs/notion/press` and `@fumadocs/sanity/press`. See [Content Sources](/docs/adapters).
