## Overview

Fumapress adds catch-all routes for the content pages and the routes of plugins to your Astro site, and a `404` route unless you have a `src/pages/404.astro`. [Deployment](/docs/astro/deployment) covers which of them render on request.

The routes of `src/pages` are yours. Routes without params take priority over the catch-all routes of Fumapress. Avoid a page and a content file at the same URL: Astro warns about the collision.

With i18n and `hideLocale: "never"`, `/` redirects to the default language, unless you have a `src/pages/index.astro`.

## Your Pages

`HomeLayout.astro` renders your page with the navbar of [`ui.baseOptions`](/docs/layouts#base-options), and the head tags of Fumapress:

```astro title="src/pages/index.astro"
---
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
---

<HomeLayout title="My Docs" description="The docs of my project.">
  <main class="flex flex-1 flex-col items-center justify-center">
    <h1 class="text-xl font-bold">Hello World</h1>
    <a href="/docs">Open Docs</a>
  </main>
</HomeLayout>
```

It takes `title`, `description`, `lang`, `alternates` and `notFound` (which renders the not found page of Fumadocs UI). Content of its `head` slot goes into `<head>`.

### Reading Content

`getPressContext()` from `@fumapress/astro/runtime` returns the site context. Export `app` from your press config to type it:

```tsx title="press.config.tsx"
export const app = createPress(/* ... */).plugins(blogPlugin({ source: "blog" }));

export default app.config({ site: { name: "Acme" } });
```

```astro title="src/pages/index.astro"
---
import { createElement } from "react";
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
import ReactContent from "@fumapress/astro/components/ReactContent.astro";
import { getPressContext } from "@fumapress/astro/runtime";
import { getBlogPosts } from "@fumapress/blog";
import { Stars } from "../components/stars";
import type { app } from "../../press.config";

const ctx = getPressContext<typeof app>();
const posts = await getBlogPosts(ctx);
---

<HomeLayout title={ctx.siteConfig.name} description="The docs of Acme.">
  <h1>{ctx.siteConfig.name}</h1>
  <ul>
    {posts.slice(0, 3).map((post) => <li><a href={post.page.url}>{post.page.data.title}</a></li>)}
  </ul>
  <ReactContent node={createElement(Stars, { initial: 42 })} />
</HomeLayout>
```

Page URLs don't include the `base` of Astro. `ctx.withBase()` adds it. See [Basics](/docs/basics#read-content-from-code).

Your pages are in the sitemap when their URL has no params. Add the others with the `additionalEntries` option of the [sitemap plugin](/docs/plugins/sitemap#additionalentries).

Your own pages give no Markdown for `llms.txt` with `routes: "all"`. See [llms.txt](/docs/plugins/llms.txt#autoredirect).

### API Routes

Your Astro API routes can read the site context:

```ts title="src/pages/api/status.ts"
import type { APIRoute } from "astro";
import { getPressContext } from "@fumapress/astro/runtime";
import type { app } from "../../../press.config";

export const prerender = false;

export const GET: APIRoute = async () => {
  const ctx = getPressContext<typeof app>();
  const pages = (await ctx.getLoader()).getPages();
  return Response.json({
    name: ctx.siteConfig.name,
    url: ctx.absoluteUrl("/"),
    pages: pages.length,
  });
};
```

### Rendering Content

A collection of `press()` that you leave out of `createPress` has no docs pages. Add it to `collections` and `src/content.config.ts` like in [Multiple Collections](/docs/astro/content#multiple-collections), then render its entries on your pages. Pass `getProviderData(Astro)` to `<Content />` so it renders with links and your [MDX components](/docs/astro/content#mdx-components):

```astro title="src/pages/guides/[slug].astro"
---
import { getCollection, render } from "astro:content";
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
import { getProviderData } from "@fumapress/astro/runtime";
import type { app } from "../../../press.config";

export async function getStaticPaths() {
  const guides = await getCollection("guides");
  return guides.map((entry) => ({ params: { slug: entry.id }, props: { entry } }));
}

const { entry } = Astro.props;
const { Content } = await render(entry);
const provider = getProviderData<typeof app>(Astro);
---

<HomeLayout title={entry.data.title}>
  <Content provider={provider} />
</HomeLayout>
```

`ReactContent.astro` renders React content, like the [React content](/docs/astro/content#react-content) of plugins:

```astro title="src/pages/timeline.astro"
---
import { createElement } from "react";
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
import ReactContent from "@fumapress/astro/components/ReactContent.astro";
import { Timeline } from "../components/timeline";
---

<HomeLayout title="Timeline">
  <ReactContent node={createElement(Timeline)} />
</HomeLayout>
```

### Not Found

Create `src/pages/404.astro` to replace the not found page:

```astro title="src/pages/404.astro"
---
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
---

<HomeLayout title="Not Found">
  <main class="p-8 text-center">This page doesn't exist.</main>
</HomeLayout>
```

With an adapter, the page of Fumapress renders in the language of the URL prefix. In static builds, `404.html` is in the default language.

## Internationalization

[i18n](/docs/internationalization) works like on Waku: content pages and the routes of plugins get the language prefixes. Your pages are not copied for each language. Create them with a `lang` param, and share the `i18n` config of your press config from a module:

```astro title="src/pages/[...lang]/about.astro"
---
import HomeLayout from "@fumapress/astro/components/HomeLayout.astro";
import { i18n } from "../../lib/i18n";

export function getStaticPaths() {
  return i18n.languages.map((lang) => ({
    params: { lang: lang === i18n.defaultLanguage ? undefined : lang },
  }));
}
---

<HomeLayout title="About">
  <main>About</main>
</HomeLayout>
```

With `hideLocale: "default-locale"`, the default language has no prefix. `HomeLayout.astro` reads the language from the URL prefix unless you pass `lang`.

## Base Path

The [`base`](https://docs.astro.build/en/reference/configuration-reference/#base) and [`trailingSlash`](https://docs.astro.build/en/reference/configuration-reference/#trailingslash) of Astro apply to the routes of Fumapress, the links of layouts and content, and the full URLs of `absoluteUrl()`, like canonical URLs and the sitemap. Plugins and the loader keep their paths without them, like `page.url`.
