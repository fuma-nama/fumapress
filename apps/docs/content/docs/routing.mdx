## Overview

Three kinds of pages:

- **Content pages** from your Markdown or MDX files, rendered by `ui.renderPage`.
- **Plugin pages** added by plugins, like the blog index or `/llms.txt`.
- **Your own pages** in `src/pages`, for landing pages and custom screens (Waku only).

## Content Pages

Content pages are generated from the source passed to `createPress`. For the [Fumadocs MDX](/docs/adapters/mdx) content source, each file under the collection directory becomes a page:

| File                           | URL                 |
| ------------------------------ | ------------------- |
| `content/docs/index.mdx`       | `/docs`             |
| `content/docs/routing.mdx`     | `/docs/routing`     |
| `content/blog/introducing.mdx` | `/blog/introducing` |

`baseDir` adds a directory prefix to generated URLs:

```tsx title="press.config.tsx"
import { createPress } from "fumapress";
import { defineDocs } from "fumadocs-mdx/macro";

const docs = defineDocs({ dir: "content/docs", docs: { async: true } });

export default createPress(docs.toFumadocsSource({ baseDir: "docs" })).config({
  site: { name: "Acme" },
});
```

The file path decides the URL and its appearance on the sidebar. See [Page Tree and Page Slugs](https://fumadocs.dev/docs/page-conventions) for the available syntax.

Content pages are rendered by `ui.renderPage`. See [Layouts](/docs/layouts) for customizing them. For other content sources, see [Content Sources](/docs/adapters).

## Plugin Pages

Plugins add views and API routes. The blog plugin creates the blog index, tag pages, and post pages. The sitemap plugin serves `/sitemap.xml`. Your own page at the same path wins over a plugin's.

See [Views](/docs/plugins/authoring#views) for creating views in a plugin.

## File-based Routing

Waku only. Route files in `src/pages` follow Waku's file-based routing conventions:

| File                       | Route         |
| -------------------------- | ------------- |
| `src/pages/index.tsx`      | `/`           |
| `src/pages/about.tsx`      | `/about`      |
| `src/pages/blog/index.tsx` | `/blog`       |
| `src/pages/_layout.tsx`    | Shared layout |

Export `getConfig()` to configure a route with `WakuRouteConfig`:

```tsx title="src/pages/pricing.tsx"
import type { WakuRouteConfig, WakuRouteProps } from "fumapress";
import type { app } from "../../press.config";

export function getConfig() {
  return { render: "static", ogImage: { title: "Pricing" } } satisfies WakuRouteConfig;
}

export default function Pricing({ lang }: WakuRouteProps<typeof app>) {
  return <main lang={lang}>Free forever.</main>;
}
```

- `render`: `"static"` (default) or `"dynamic"`.
- `staticPaths`: the paths of a static page with slugs.
- `autoI18n`: defaults to `true`. Set `false` to keep a single copy at its own path, rendered in the default language.
- `ogImage`: the [OG image](/docs/plugins/takumi#route-images) of the page.

Props are typed with `WakuRouteProps<typeof app, "/showcase/[slug]">`:

```tsx title="src/pages/showcase/[slug].tsx"
import type { WakuRouteConfig, WakuRouteProps } from "fumapress";
import type { app } from "../../../press.config";

const items: Record<string, { title: string; description: string }> = {
  acme: { title: "Acme", description: "Docs of Acme" },
};

export function getConfig() {
  return {
    render: "static",
    staticPaths: Object.keys(items),
    ogImage(params) {
      const item = items[params.slug as string];
      return { title: item?.title, description: item?.description };
    },
  } satisfies WakuRouteConfig;
}

export default function Showcase({ slug, lang }: WakuRouteProps<typeof app, "/showcase/[slug]">) {
  const item = items[slug];
  if (!item) return null;
  return (
    <main lang={lang}>
      <title>{item.title}</title>
      {item.description}
    </main>
  );
}
```

When i18n is enabled, a file-based page is registered once per language under the language prefix and with a `lang` prop. See [Internationalization](/docs/internationalization#routing) for the URL structure.

### Layouts

`_layout.tsx` wraps the pages of its folder with a layout, like the [Home Layout](/docs/layouts/home#your-own-pages).

### Not Found

`src/pages/404.tsx` renders your own 404 page. It wins over a plugin's `/404` view.

```tsx title="src/pages/404.tsx"
import { getPressContext } from "fumapress";
import type { app } from "../../press.config";

export default function NotFound() {
  return <main>Not found on {getPressContext<typeof app>().siteConfig.name}</main>;
}
```

### API Routes

Place files under `src/pages/_api`. Export handlers named after HTTP methods (`GET`, `POST`, etc.):

```ts title="src/pages/_api/version.ts"
export async function GET() {
  return Response.json({ version: "1.0.0" });
}
```

Or a default export to handle all methods:

```ts title="src/pages/_api/version.ts"
export default async function handler(req: Request) {
  return Response.json({ version: "1.0.0" });
}
```

API routes are dynamic by default. Under `mode: "static"` they are prerendered instead, which supports only a single `GET` handler.

<Callout type='warn'>

Fumapress creates the default catch-all route for content pages. Avoid defining a file-based route and a content page with the same URL.

</Callout>

## Client

Waku only. Import navigation helpers from `fumapress/client`.

### `<Link>`

Use `<Link>` for in-app links instead of `<a>`. It enables client-side navigation and works with [link validation](/docs/plugins/link-validation) during build.

```tsx
import { Link } from "fumapress/client";

<Link href="/about">About</Link>;

// skip scrolling to the top
return (
  <Link href="/docs" scroll={false}>
    Docs
  </Link>
);
```

Use a normal `<a>` for external URLs.

### `useRouter()`

`useRouter()` reads the current location and navigates programmatically:

```tsx
"use client";

import { useRouter } from "fumapress/client";

function Nav() {
  const router = useRouter();

  return (
    <div>
      <p>
        {router.path}
        {router.query ? `?${router.query}` : ""}
      </p>
      <button type="button" onClick={() => router.push("/about")}>
        About
      </button>
    </div>
  );
}
```

`push` and `replace` accept the same `scroll` option as `<Link>`:

```tsx
router.push("/docs", { scroll: false });
router.replace("/docs", { scroll: true });
```

The router also exposes:

- `back()` / `forward()`: history navigation.
- `reload()`: re-render the current route.
- `prefetch(to)`: preload a route before navigating.
- `hash`: the current location hash.

### `useNavigationStatus()`

Inside a `<Link>`, `useNavigationStatus().pending` is `true` while its navigation is in progress.

## Server Redirects

Waku only. On the server, use `redirect` to redirect to another route:

```tsx title="src/pages/old-docs.tsx"
import { redirect } from "fumapress/router";

export default function Page() {
  redirect("/docs");
}
```

Or `notFound` to show a not found screen.

```tsx title="src/pages/secret.tsx"
import { notFound } from "fumapress/router";

export default function Page() {
  if (!hasAccess()) notFound();

  return <main>Secret</main>;
}
```
